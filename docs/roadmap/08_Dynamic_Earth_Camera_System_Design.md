我看完了。我的判断是：**现有草案大约有七成方向正确，可以作为第一轮实验说明，但还不适合作为最终技术方案直接实施。**

它准确找到了两个核心问题：现有预设缺少“完整地球但有明显留白”的中景距离；相机位置和 FOV 只有硬切，没有完整的过渡系统。保留默认视角、先在调试面板验证，也能有效控制风险。

但现在的方案仍有几个结构性问题。

## 一、现有方案的问题

### 1. “视角”“运动”“主题”混在了一起

草案中的内容实际上属于三种不同对象：

| 草案内容                                 | 实际类型           |
| ---------------------------------------- | ------------------ |
| `lowPassHero`、`blueMarble`、`polarTilt` | 静态视角           |
| `orbitDescent`、`terminatorSweep`        | 相机或地球运动序列 |
| `goldenHourGlobe`、搭配 `deepNight`      | 光照和视觉主题     |

如果全部放进 `CAMERA_PRESETS`，后续会出现大量重复组合，例如：

- blueMarbleDeepNight
- blueMarbleSunset
- blueMarbleTerminator
- polarTiltSunrise
- polarTiltDeepNight

最终不是八个视角，而是几十个参数组合。

正确做法是拆成：

**静态视角 + 运动序列 + 光线修饰器 + 产品触发规则。**

------

### 2. `lowPassHero` 的参数可能过于激进

草案建议：

```js
cameraOffsetY: 1.4
cameraOffsetZ: 2.9
fov: 23
```

按照草案所述地球半径为 2.0 粗略计算，相机距离地心约为 3.22。这个距离配合 23° 窄视场角，地球会远远超出屏幕范围。

它可能得到的不是“低空掠过的地球特写”，而是：

- 画面完全被地表覆盖；
- 看不到足够明显的地球曲率；
- 地平线可能被挤出画面；
- 转场时产生突然冲向地面的感觉。

方向没有错，但建议先把 Z 放在 **3.8—4.6** 的区间测试，再逐步靠近，而不是直接锁定 2.9。

------

### 3. 衰减插值不适合承担所有动画

草案建议继续使用：

```js
current += (target - current) * factor
```

它适合地球缓慢“对准”某个方向，但不适合所有相机运动。

主要问题是：

- 数学上永远不会真正到达目标；
- “持续15秒”很难严格成立；
- 起始变化快，末尾拖得很长；
- 不同距离的运动，体感速度不一致；
- 经纬度扫动会出现明显先快后慢。

更合理的是：

- 地球朝向继续使用四元数 SLERP；
- 镜头切换使用固定进度 `0—1`；
- 根据运动类型选择 easing；
- 扫动使用恒定角速度；
- 下降使用缓入缓出；
- 随时允许从当前状态中断并接续新动画。

不需要引入动画库，自己实现几个 easing 函数即可。

------

### 4. 同时改变距离、FOV 和看向点，容易产生“镜头呼吸”

从 globe 到 lowPassHero，如果同时：

- 相机前移；
- FOV 变窄；
- lookAt 下移；
- 地球旋转；

画面中的地球大小会先突然膨胀，再缓慢稳定，产生类似镜头变焦时的“呼吸感”。

每段动画最好确定一个主要动作：

- **Dolly**：主要改变相机距离；
- **Orbit**：主要改变相机方位；
- **Pan/Target Shift**：主要改变构图中心；
- **Zoom**：只用于小范围修正 FOV。

不要四项同时大幅变化。

------

### 5. 现在还是“参数驱动”，没有转成“构图驱动”

当前方案直接确定 Z 和 FOV，但真正影响美感的是：

- 地球直径占画面高度多少；
- 地球中心偏离画面中心多少；
- 地平线处在画面的什么位置；
- 晨昏线是什么角度；
- 黑色留白在哪一侧；
- 手机状态栏、播放控件是否遮住主体。

更稳定的方式是先定义：

```js
earthDiameterPct: 0.72
anchorX: 0.50
anchorY: 0.54
horizonY: 0.42
rollDeg: 8
```

再根据屏幕尺寸、FOV 和地球半径反算相机距离。

这样同一视角在桌面、手机竖屏和横屏上不会完全变样。

------

## 二、可以采用的四种设计方向

### 方案A：尺度递进型

核心是从地面、近地轨道、完整地球到深空，形成明确的空间尺度。

适合表现：

- 从地球缓慢下降到城市；
- 播放开始或结束；
- 长时间沉浸；
- 产品的标志性开场。

视角顺序：

```text
地表掠过 → 地球边缘 → 默认地球 → 蓝色弹珠 → 远轨道 → 深空
```

优点是叙事最清楚，缺点是单独使用久了会比较像传统地球应用。

------

### 方案B：光线叙事型

不把重点放在相机有多远，而是放在晨昏线、城市灯光和太阳方向。

可以形成：

- 晨昏线正面；
- 新月形地球；
- 城市灯光侧；
- 日出边缘；
- 极夜和极昼；
- 深蓝海洋全景。

优点是最符合目前 RodiO 已经投入较多的时段调色系统，也最容易形成独特视觉语言。

缺点是必须明确太阳方向、地球方向和相机方向分别处于什么坐标空间，不能只改变经纬度后期待晨昏线自然移动。

------

### 方案C：构图美学型

不追求完整地展示地球，而是把地球当作摄影对象。

主要构图包括：

- 居中肖像；
- 左下角偏置；
- 右侧大面积黑色负空间；
- 斜向晨昏线；
- 极区对角线；
- 半个地球切出屏幕；
- 地平线贴近下三分之一。

这套方案最容易接近苹果锁屏、电影海报和唱片封面的质感。

优点是美感强；缺点是需要增加 `anchorX`、`anchorY` 和 `rollDeg`，仅靠现在的 Y/Z 偏移不够。

------

### 方案D：音乐状态联动型

镜头不是让用户手动选择，而是根据音乐状态变化：

| 音乐状态     | 推荐镜头               |
| ------------ | ---------------------- |
| 暂停或待机   | blueMarble，缓慢自转   |
| 歌曲开始     | 从远轨道推进到默认地球 |
| 低能量段落   | 晨昏线肖像或深空       |
| 高能量段落   | 近地边缘或轨道弧线     |
| 歌曲切换     | 小幅方位转换           |
| 长时间无操作 | 自动进入慢速巡航       |

优点是和 RodiO 产品定位结合最深。

但第一阶段不应该直接做音频实时驱动，否则镜头频繁变化会显得廉价。初期只根据“播放、暂停、切歌、空闲”四种状态触发即可。

------

## 三、推荐的最终融合方案

建议以**构图美学型为主体，尺度递进型负责运动，光线叙事型负责视觉变化，音乐状态型负责产品触发**。

下面这份可以直接作为给 Evan 的新版技术规格。

# RodiO 地球视角系统重设计 v2.0

## 一、设计目标

本次不只是增加若干相机参数，而是建立一套可以持续扩展的地球镜头系统。

系统拆分为四层：

1. `CAMERA_VIEWS`：静态镜头构图；
2. `CAMERA_SEQUENCES`：镜头运动过程；
3. `CAMERA_MODIFIERS`：晨昏线、主题、辉光等视觉修饰；
4. `CAMERA_TRIGGERS`：播放、暂停、空闲等产品触发规则。

不得再把静态视角、运动过程和主题效果全部定义成 Camera Preset。

------

## 二、第一层：静态镜头体系

### 1. `homeGlobe`

保留现有默认 `globe` 参数，一个数值都不修改。

用途：

- 正常播放默认状态；
- 所有自动镜头结束后的返回位置；
- 旧体验兼容基线。

------

### 2. `portraitMarble`

完整地球肖像，对应“蓝色弹珠”构图。

目标构图：

- 地球直径占屏幕高度约 68%—78%；
- 四周存在明确黑色留白；
- 地球中心略低于画面中心；
- FOV 保持在 26°—28°；
- 初始 Z 测试区间为 9.0—11.5。

建议初始测试参数：

```js
{
  lat: 31.23,
  lon: 121.47,
  fov: 28,
  cameraOffsetY: 0.0,
  cameraOffsetZ: 10.5,
  lookAtY: -0.08,
  anchorX: 0.50,
  anchorY: 0.54,
  rollDeg: 0
}
```

该视角不强制绑定 `deepNight`。主题和相机必须解耦。

------

### 3. `limbHero`

地球边缘近距离特写，用于表现地球曲率、大气辉光和地表纹理。

目标构图：

- 地球主体明显超出画面；
- 地平线或地球边缘仍然清楚可见；
- 地球边缘位于画面下方或侧下方；
- 不允许画面退化成纯地表贴图。

第一轮不要直接使用 Z=2.9，建议先测试：

```js
{
  fov: 24-28,
  cameraOffsetY: 0.8-1.3,
  cameraOffsetZ: 3.8-4.6,
  lookAtY: -0.25~-0.55
}
```

测试完成后再逐步靠近。

------

### 4. `horizonSkim`

接近地表的横向地平线构图。

与 `limbHero` 的区别：

- `limbHero` 强调球体边缘；
- `horizonSkim` 强调地平线横向延伸和地表空间感。

目标构图：

- 地平线位于画面高度的 38%—55%；
- 天空和地表均有明确面积；
- 不追求完整地球轮廓；
- 允许轻微横向运动。

------

### 5. `terminatorPortrait`

完整地球加晨昏线的标志性镜头。

相机距离基本沿用 `portraitMarble`，主要通过地球朝向和太阳方向构图。

目标构图：

- 晨昏线与垂直方向形成约 20°—35°夹角；
- 夜侧城市灯光可见；
- 日侧不能完全过曝；
- 地球可以向画面左侧或右侧偏移 5%—10%，为暗部留出空间。

该镜头不定义独立的 deepNight 版本，光线由 Modifier 控制。

------

### 6. `polarDiagonal`

高纬度斜向构图。

建议参数区间：

```js
{
  lat: 62-75,
  lon: 70-110,
  fov: 24-28,
  cameraOffsetY: 1.2-1.8,
  cameraOffsetZ: 5.5-7.0,
  rollDeg: 8-14
}
```

该视角必须支持相机 Roll。只改变纬度不能稳定地产生对角线构图。

------

### 7. `cityAnchor`

以用户关注城市为视觉锚点，但不采用传统地图式居中放大。

以上海为默认锚点：

- 上海位于画面中心偏下或偏侧；
- 同时保留地球曲率；
- 不追求精确导航定位；
- 用于形成“我的城市正在进入夜晚”的情感联系。

城市坐标和镜头构图应分别配置，避免更换城市后构图完全失效。

------

### 8. `farOrbit`

补充默认地球和现有 `deepSpace` 之间的巨大距离空档。

目标构图：

- 地球直径占屏幕高度 25%—40%；
- 仍可辨认海洋、陆地和城市灯光；
- 适合作为镜头运动的起点；
- 不替代现有极远的 `deepSpace`。

现有 `deepSpace` 可以继续保留为特殊或调试视角。

------

## 三、第二层：镜头运动序列

### 1. `descentToEarth`

表现从太空缓慢接近地球。

推荐路径：

```text
farOrbit → portraitMarble → homeGlobe → limbHero
```

总时长建议 12—16 秒。

不要直接从远景线性插值到近景，应拆成三个阶段：

1. 远轨道接近完整地球；
2. 完整地球进入默认构图；
3. 默认构图缓慢压向地球边缘。

每一阶段独立控制距离、朝向和 FOV，避免同时发生剧烈变化。

------

### 2. `terminatorSweep`

表现晨昏线和城市灯光从画面中缓慢扫过。

实现原则：

- 相机距离保持不变；
- FOV 保持不变；
- 只改变地球朝向或轨道方位；
- 使用恒定角速度；
- 默认持续 18—28 秒；
- 不使用先快后慢的 decay。

“45°到125°”应明确为经度、轨道方位角或地球自转角，不能只用一个模糊的 angle 字段。

------

### 3. `orbitalArc`

相机围绕地球做小范围轨道弧线运动。

建议：

- 方位变化 20°—45°；
- 高度基本不变；
- 持续 8—14 秒；
- 可带 2°—5°的轻微 Roll；
- 地球主体大小保持相对稳定。

该运动比单纯旋转地球更有立体感，但不得高速运行。

------

### 4. `returnHome`

任何镜头返回默认视角的统一动画。

建议时长 3.5—5 秒。

要求：

- 从当前实时状态开始，而不是从预设起点重新开始；
- 新动画触发时取消旧动画；
- 地球朝向使用 SLERP；
- 相机位置使用球坐标或轨道坐标插值；
- 动画结束后精确写入目标值，避免无限趋近。

------

## 四、动画数学与控制规则

不引入外部动画库。

所有固定时长动画使用归一化进度：

```js
t = clamp((now - startTime) / duration, 0, 1)
```

建议提供：

```js
linear(t)
easeInOutCubic(t)
easeOutCubic(t)
smoothstep(t)
```

使用规则：

| 运动         | 曲线           |
| ------------ | -------------- |
| 晨昏线扫动   | linear         |
| 轨道弧线     | easeInOutCubic |
| 接近地球     | easeInOutCubic |
| 返回默认镜头 | easeOutCubic   |

地球朝向使用四元数 SLERP。

相机位置优先使用球坐标插值，不直接对 XYZ 做大跨度线性插值，避免路径穿入地球或产生不自然的直线运动。

FOV 只作为构图修正项。大范围推进主要由相机距离完成。

所有动画必须支持：

```js
cancelCurrentTransition()
transitionFromCurrentState()
```

------

## 五、构图参数体系

在现有参数之外增加：

```js
{
  earthDiameterPct,
  anchorX,
  anchorY,
  horizonY,
  rollDeg,
  safeAreaProfile
}
```

说明：

- `earthDiameterPct`：地球直径占屏幕高度比例；
- `anchorX/anchorY`：地球视觉中心位置；
- `horizonY`：近地镜头中的地平线位置；
- `rollDeg`：相机滚转角；
- `safeAreaProfile`：桌面、手机竖屏、手机横屏的安全区域。

相机距离应尽量由目标构图比例反算，而不是全部使用固定 Z。

窗口尺寸或设备方向改变时，应重新计算镜头构图。

------

## 六、辉光适配

不得为每个视角手工复制一套 Rim Glow 参数。

根据地球在屏幕上的投影半径自动缩放：

```js
effectiveRimWidth =
  clamp(
    baseRimWidth * projectedRadius / referenceRadius,
    minRimWidth,
    maxRimWidth
  )
```

地球变小时，辉光宽度同步变窄；地球靠近时，辉光允许适当变宽。

每个静态镜头只允许提供一个小范围 `rimScale` 修正系数，不直接覆盖整套主题配置。

- 手机竖屏；
- 手机横屏；

- noon；

- deepNight。

| 晨昏线角度   | 是否形成明确构图       |

截图不能只选最好的一张，需要建立统一的视角对比矩阵。

《产品方案》里，地球运动并不是偶尔出现的装饰，而是一首歌完整仪式的一部分：歌曲开始后地球随情绪转动，结束前减速，回到出发位置，再进入两秒静止；同时还设计了 BPM、曲风、歌名、歌手和特殊时刻触发的不同视觉行为。只有三四个静态构图和两条转场，无法承载这套产品设定。

另一方面，《开发路线》把“地球三维旋转”和“彩蛋库”放在 v2.0，但《产品方案》又把旋转写进每首歌曲的核心仪式。这两份文件在优先级上存在冲突：**完整彩蛋库可以以后做，但通用动态镜头引擎必须提前成为当前地球视觉基础的一部分。**

此前的相机草案准确找出了现有八个预设缺乏中距离构图、没有平滑转场等问题，但它解决的主要还是“镜头点位”，还没有解决“播放器长期播放数百首歌曲时，如何持续产生变化”的问题。

## 一、不是增加到二十个相机预设

直接增加二十至三十个 `CAMERA_PRESETS`，短期看起来丰富，长期一定会失控。

因为真正决定动态观感的是五层组合：

| 层级     | 决定什么                        |
| -------- | ------------------------------- |
| 静态构图 | 地球在画面中的大小和位置        |
| 运动轨迹 | 相机或地球沿什么路径运动        |
| 动态节奏 | 快慢变化、是否呼吸、何时减速    |
| 世界状态 | 真实太阳、晨昏线、天气、月相    |
| 歌曲语义 | BPM、能量、风格、歌名和特殊彩蛋 |

正确目标不是做三十个互不相干的动画，而是建立一套**镜头语法系统**：

- 9—10种基础构图；
- 12—14种运动原语；
- 6种速度与情绪曲线；
- 24种日常动态模式；
- 8种特殊或稀有模式。

同一个动态模式再根据方向、幅度、速度和真实世界状态变化，可以形成上百种实际观感，但代码仍然可管理。

------

## 二、一个重要边界：真实地球不能被音乐篡改

《产品方案》的核心原则是“真实不是装饰，而是底层逻辑”。因此要明确：

### 绝对不能随音乐改变的内容

- 太阳真实方位；
- 晨昏线真实位置；
- 月相；
- 季节和黄赤交角；
- 云和天气事实；
- 城市实际处于白天还是夜晚。

### 可以随音乐改变的内容

- 观察者站在哪里；
- 镜头距离；
- 镜头绕地球的路径；
- 运动速度和幅度；
- 构图中心；
- 镜头轻微滚转；
- 视觉运动的节奏。

换句话说：

> 音乐不能改变宇宙正在发生什么，但可以改变用户从哪里、以什么节奏观看它。

这样既能丰富，又不破坏 RodiO 的产品哲学。

## 三、建议的完整动态模式体系

# RodiO 动态地球镜头系统 v3.0

## 1. 系统目标

为长期连续播放提供足够丰富、但不显得像音乐可视化插件的地球动态。

动态系统需要满足：

1. 每首歌曲可以选择不同的运动方式；
2. 相邻歌曲不出现明显重复；
3. 慢歌不被强运动打扰；
4. 快歌有能量，但不进行廉价的逐拍抖动；
5. 所有真实天文和气象状态保持不变；
6. 每首歌结束前自然减速，并回到歌曲开始时的锚点；
7. 手机端可以按性能降级。

------

# 2. 基础构图库

基础构图只决定“地球在画面里是什么样”，不定义运动。

## C01 · Home Globe

现有默认地球视角。

用途：

- 常规播放；
- 动态结束后的稳定锚点；
- 系统无匹配结果时的安全回退。

------

## C02 · Portrait Marble

完整地球肖像。

特征：

- 地球占屏幕高度约 68%—78%；
- 周围有明显黑色留白；
- 适合晨昏线、城市灯光和云层展示。

------

## C03 · Far Orbit

远轨道完整地球。

特征：

- 地球占屏幕高度约 28%—42%；
- 周围宇宙空间明显增加；
- 适合空灵、宇宙、后摇和环境音乐。

------

## C04 · Limb Hero

地球边缘特写。

特征：

- 地球大幅超出屏幕；
- 保留明显曲率；
- 强调地表、云层和大气边缘。

------

## C05 · Horizon Skim

接近地平线的低轨视角。

特征：

- 天空和地表同时存在；
- 地平线位于画面中部附近；
- 适合飞行感和流动性强的歌曲。

------

## C06 · Terminator Portrait

晨昏线主题构图。

特征：

- 地球完整可见；
- 晨昏线以斜线切过画面；
- 夜侧城市灯光存在；
- 相机只负责构图，不修改真实太阳方向。

------

## C07 · Polar Diagonal

极区斜向构图。

特征：

- 高纬度；
- 轻微相机 Roll；
- 地球轴线形成明显对角构图。

------

## C08 · City Anchor

城市锚点视角。

特征：

- 用户所在城市或目标城市位于偏中心位置；
- 同时保留地球曲率；
- 用于“此刻”“飞去某个地方”和具有地域性的歌曲。

------

## C09 · Ocean Expanse

海洋主导构图。

特征：

- 大陆处于边缘；
- 海面占据大部分画面；
- 适合纯音乐、氛围、海洋意象和空间感强的歌曲。

------

## C10 · Deep Space

极远地球。

特征：

- 地球成为小型天体；
- 星空成为画面主体；
- 不作为高频日常模式，只在特殊歌曲和段落使用。

# 3. 运动原语库

以下原语可以单独使用，也可以组合成完整模式。

## M01 · Hold

几乎完全静止，只保留真实地球自转和极小幅度漂移。

## M02 · Breathe

相机距离以极低频率轻微靠近和远离。

建议幅度不超过当前距离的 1.5%—3%。

## M03 · Longitude Drift

沿经度方向缓慢移动，表现时区流动。

## M04 · Latitude Drift

沿纬度方向移动，表现极区、季节和轴倾变化。

## M05 · Diagonal Drift

经度和纬度同时变化，形成斜向轨迹。

## M06 · Orbital Arc

相机沿地球外部做一段小角度轨道弧线。

## M07 · Flyby

相机从地球边缘缓慢掠过。

## M08 · Approach

从远处缓慢接近地球。

## M09 · Retreat

从近处缓慢拉远。

## M10 · Spiral

在接近或远离过程中加入小幅轨道旋转。

## M11 · Target Shift

地球大小基本不变，只改变画面中的构图中心。

## M12 · Roll

相机绕自身视轴轻微滚转。

日常幅度建议控制在 2°—8°。

## M13 · Terminator Track

沿晨昏线的方向移动观察位置。

不改变晨昏线本身，只改变观察角度。

## M14 · Return

从当前实时状态回到歌曲开始时的锚点。

# 4. 日常动态模式库

## A组：静谧凝视

适合 Ambient、极简、纯钢琴、低能量古典、冥想音乐。

### D01 · Still Earth｜静止地球

构图：

- Home Globe 或 Portrait Marble。

运动：

- Hold；
- 只保留真实自转；
- 几乎感觉不到人为镜头运动。

适用特征：

- BPM 很低；
- 能量很低；
- 长音和留白较多。

------

### D02 · Orbital Breathing｜轨道呼吸

运动：

- Breathe；
- 极轻微上下漂移；
- 一个完整呼吸周期约 18—35 秒。

观感：

- 地球像悬浮在黑暗中呼吸。

------

### D03 · Moonlit Drift｜月下漂移

构图：

- Portrait Marble 或 Terminator Portrait。

运动：

- 极慢 Diagonal Drift；
- 幅度较小；
- 月亮存在时优先选择。

适合：

- 女声；
- 梦幻流行；
- 氛围电子；
- 低能量抒情。

------

### D04 · Polar Silence｜极地静默

构图：

- Polar Diagonal。

运动：

- Hold + 极轻微 Latitude Drift；
- 结束前几乎完全静止。

适合：

- 冷感音乐；
- 北欧氛围；
- 室内乐；
- 冬季歌曲。

------

## B组：自然流动

适合抒情流行、民谣、世界音乐、轻电子和有持续旋律线的音乐。

### D05 · Timezone Flow｜时区漂流

构图：

- Home Globe 或 Portrait Marble。

运动：

- Longitude Drift；
- 匀速经过若干经度；
- 城市灯光和晨昏区域自然进入画面。

------

### D06 · Seasonal Float｜季节漂移

运动：

- Latitude Drift；
- 轻微 Roll；
- 让极区和轴倾逐渐显现。

适合：

- 古典；
- 民谣；
- 具有季节感的歌曲；
- 长旋律纯音乐。

------

### D07 · Diagonal Journey｜斜向远行

运动：

- Diagonal Drift；
- 同时改变经纬度；
- 不改变镜头距离。

适合：

- 旅行感；
- 公路感；
- 世界音乐；
- 中等能量抒情歌曲。

------

### D08 · Ocean Current｜洋流

构图：

- Ocean Expanse。

运动：

- Longitude Drift + 小幅 Orbital Arc；
- 速度稳定；
- 不出现明显加减速。

适合：

- 海洋意象；
- 氛围音乐；
- Chillout；
- Bossa Nova；
- 轻爵士。

------

### D09 · Cloud Passage｜穿云

构图：

- Horizon Skim 或 Limb Hero。

运动：

- Flyby；
- 云层和地表之间产生视差；
- 相机不进入云层内部，避免穿模。

适合：

- 空灵人声；
- 飞行感歌曲；
- 后摇前半段；
- 具有持续推进感的音乐。

------

## C组：空间尺度

适合电影配乐、后摇、交响乐、史诗感音乐和情绪变化明显的歌曲。

### D10 · Earth Approach｜靠近地球

路径：

```text
Far Orbit → Portrait Marble → Home Globe
```

运动：

- Approach；
- FOV 只做小幅修正；
- 主要通过相机距离表现接近。

------

### D11 · Leaving Earth｜离开地球

路径：

```text
Home Globe → Portrait Marble → Far Orbit
```

运动：

- Retreat；
- 结束前停在较远位置；
- 歌曲最后再缓慢回到起点。

适合：

- 离别；
- 宇宙；
- 空旷；
- 逐渐消散的歌曲。

------

### D12 · Low Orbit Flyby｜低轨掠过

构图：

- Limb Hero → Horizon Skim。

运动：

- Flyby + 小幅 Roll；
- 地表和云层形成明显视差。

适合：

- Post-rock；
- Progressive；
- 中高能量器乐；
- 具有推进感的电子音乐。

------

### D13 · Horizon Rising｜地平线升起

构图：

- 从地表占主导逐渐露出地球曲率。

运动：

- Approach 或 Target Shift；
- 视觉上像从地面慢慢看见整个世界。

适合：

- 渐强音乐；
- 日出时段；
- 交响乐；
- 具有“展开感”的歌曲。

------

### D14 · Cosmic Reveal｜宇宙揭示

路径：

```text
局部暗面 → 完整地球 → 星空与地球共存
```

运动：

- Target Shift + Retreat；
- 不改变真实光照。

适合：

- 音乐前段克制、后段展开的歌曲；
- 电影配乐；
- 大动态古典。

------

## D组：节奏和能量

适合电子、Dance、Funk、部分摇滚和节奏感明显的流行音乐。

这些模式不能逐拍让相机震动。节奏只影响长周期运动参数。

### D15 · Pulse Orbit｜脉冲轨道

运动：

- Orbital Arc；
- 轨道速度随歌曲能量缓慢起伏；
- 一次速度变化周期约 8—20 秒。

适合：

- 电子；
- Synthwave；
- 中速舞曲；
- 节奏感明显但不狂躁的歌曲。

------

### D16 · Elastic Orbit｜弹性环绕

运动：

- 相机向一侧运动后缓慢回弹；
- 使用柔和的正弦或 easeInOut 曲线；
- 不进行快速来回摆动。

适合：

- Jazz；
- Soul；
- R&B；
- 律动型流行。

------

### D17 · Spiral Ascent｜螺旋上升

运动：

- Spiral + Retreat；
- 地球逐渐变小；
- 同时改变观察方位。

适合：

- 渐强电子；
- Trance；
- Progressive House；
- 有明确上升感的音乐。

------

### D18 · Energy Descent｜能量俯冲

运动：

- Far Orbit 向 Home Globe 快速但平滑接近；
- 之后转入较慢的 Orbital Arc；
- 不能接近到失去地球曲率。

适合：

- 强烈开场；
- 摇滚；
- 高能电子；
- 电影预告式音乐。

该模式使用频率必须较低。

------

### D19 · Restless Planet｜不安星球

运动：

- 小幅不规则 Orbital Arc；
- 运动方向偶尔变化；
- 不做镜头抖动。

适合：

- 实验音乐；
- Noise；
- 工业音乐；
- 重金属。

该模式只能使用低幅度，避免眩晕。

------

## E组：叙事运动

适合具有地点、时间、季节和故事感的歌曲。

### D20 · Day to Night｜昼夜穿越

运动：

- 沿经度缓慢移动；
- 观察不同区域进入日侧和夜侧；
- 太阳方向完全真实。

适合：

- 时间主题；
- 城市夜晚；
- 长篇器乐；
- 世界音乐。

------

### D21 · City to City｜城市迁移

路径：

```text
城市A → 海洋或大陆过渡 → 城市B
```

运动：

- Diagonal Drift；
- 必要时配合 Approach 和 Retreat；
- 不采用地图导航式直线跳转。

适合：

- 地名歌曲；
- “飞去某个地方”；
- 国别或城市主题音乐。

------

### D22 · The Other Side｜地球另一面

运动：

- 从用户所在位置缓慢旋转至对跖区域；
- 途中经过晨昏线；
- 到达后停留短暂时间。

适合：

- 孤独感；
- 世界同时性；
- 长篇 Ambient；
- 特殊天外来信。

不能高频使用。

------

### D23 · Return Journey｜回程

一首歌前半段逐渐远离出发位置，后半段以不同路径返回。

结构：

```text
出发 → 远行 → 停留 → 回到歌曲起点
```

适合：

- 有完整叙事弧线的流行歌；
- 民谣；
- 电影配乐；
- 情绪经历明显的歌曲。

------

### D24 · World Turning｜世界继续

不设置明显高潮动作。

运动：

- Longitude Drift；
- 很慢的 Orbital Arc；
- 动画持续整首歌；
- 结束前自然减速。

这是通用度最高的动态模式，可作为默认动态模式之一。

# 5. 特殊动态模式

特殊模式不进入常规随机池，只由明确条件触发。

## S01 · Reverse Time｜时间倒流

地球和主要动态反向运行。

用于：

- 《反方向的钟》等明确语义彩蛋。

------

## S02 · Zero Gravity｜失重

相机和界面元素出现极轻微无重力漂浮。

用于：

- Weightless；
- 太空主题；
- 特定 Ambient。

------

## S03 · Deep Space Departure｜深空离去

地球持续缩小，直到接近一个小点。

用于：

- 宇宙标题；
- Space Oddity；
- 少量特殊歌曲。

------

## S04 · Storm Orbit｜风暴轨道

轨道速度和方向出现可控的不稳定感。

用于：

- 暴雨；
- 雷暴；
- 重金属；
- 噪音。

天气事实和歌曲条件必须至少满足一项，不能随意使用雷暴视觉。

------

## S05 · Absolute Stillness｜绝对静止

人为动态完全停止，只保留不可取消的真实天文变化。

用于：

- Satie；
- 《存在》；
- 日食关键时刻；
- 极特殊静默歌曲。

------

## S06 · Dawn Chase｜追逐黎明

镜头沿晨昏线移动，让日出边缘在画面中持续存在。

只在真实黎明或“飞去”目标地点处于黎明时使用。

普通歌曲不能伪造黎明。

------

## S07 · Opposite Rotation｜反向轨道

相机运动方向与地球正常自转方向相反，但地球真实自转本身不修改。

这可以产生“逆流”感，又不篡改真实物理状态。

------

## S08 · Celestial Witness｜天文见证

日食、月食、流星雨、极光等真实事件发生时：

- 相机运动减弱；
- 让真实事件成为主体；
- 音乐短暂压低；
- 不增加无关动作。

------

# 6. 动态曲线体系

每个模式选择一种运动曲线。

## E01 · Constant

匀速。

适合：

- 经度扫动；
- 晨昏线追踪；
- 大洋漂流。

## E02 · Ease In Out

缓慢启动，中段稳定，结束减速。

适合：

- 轨道运动；
- 城市迁移；
- 斜向远行。

## E03 · Ease Out

开始较明显，随后逐渐平静。

适合：

- 歌曲开头的接近动作；
- 从强烈开场进入稳定状态。

## E04 · Breathing

低频正弦变化。

适合：

- Ambient；
- 慢歌；
- 静止镜头。

## E05 · Crescendo

运动能量随歌曲进行逐渐增强。

适合：

- 渐强音乐；
- Post-rock；
- 交响乐。

## E06 · Dissolve

运动逐渐衰减至接近静止。

适合：

- 渐弱结尾；
- 离别；
- Ambient；
- 深夜歌曲。

# 7. 歌曲选择引擎

动态模式不能只按歌曲类型硬匹配。

## 输入信息

### 音乐特征

- BPM；
- 能量；
- 动态范围；
- 是否器乐；
- 人声密度；
- 节奏稳定度；
- 情绪倾向；
- 歌曲时长；
- 标题、歌词和歌手语义。

### 世界特征

- 当前九段时光；
- 太阳和晨昏线；
- 天气；
- 月相；
- 云量；
- 节气；
- 特殊天文事件；
- 目标地点。

### 系统特征

- 当前镜头状态；
- 最近五首歌使用过的模式；
- 当前设备性能；
- 是否为手机竖屏；
- 电量和低功耗状态；
- 用户是否正在操作界面。

------

## 推荐评分模型

```text
模式得分 =
音乐匹配度        35%
世界状态兼容度    25%
近期去重奖励      15%
前后歌曲连续性    10%
设备性能适配      10%
特殊语义触发       5%
```

特殊彩蛋命中时，可以覆盖普通评分。

------

## 去重规则

1. 同一个动态模式五首歌内不得重复；
2. 同一个模式家族最多连续出现两首；
3. 连续两首高运动模式后，下一首强制进入低运动池；
4. Deep Space 类模式至少间隔八首；
5. 特殊模式不进入普通历史去重，但触发后设置冷却时间；
6. 同一首歌在同一天可以保持相似镜头气质，但不必完全复现同一条轨迹。

------

# 8. 每首歌的动态结构

每首歌不应从第一秒一直匀速运动到最后。

## 阶段一：来信与建立

歌曲开始后的前 8—15 秒：

- 天外来信出现；
- 镜头保持稳定或只做微小动作；
- 让用户先建立空间感。

## 阶段二：主要运动

歌曲中段：

- 执行本首歌曲选中的主要动态模式；
- 运动强度逐渐稳定；
- 不因每个鼓点改变镜头。

## 阶段三：情绪收束

歌曲结束前约 10—20 秒：

- 主运动逐渐减速；
- 开始返回歌曲起点；
- 特殊模式也必须退出。

## 阶段四：回到锚点

歌曲结束前：

- 精确回到本首歌曲开始时的视角与地理锚点；
- 不一定回到全局 `homeGlobe`；
- 保证一首歌形成完整闭环。

## 阶段五：两秒静止

歌曲结束后：

- 镜头停止人为运动；
- 只保留真实宇宙运行；
- 下一封信开始凝结。

------

# 9. 动态强度分级

同一个模式需要三档强度，而不是为每档重新建立模式。

## Low

- 运动幅度小；
- 慢速；
- 手机默认优先；
- 慢歌和深夜优先。

## Medium

- 日常标准强度；
- 桌面和横屏优先；
- 大部分流行、民谣和器乐使用。

## High

- 轨道距离、Roll 和速度更明显；
- 只用于高能歌曲、电影配乐和特殊彩蛋；
- 不得连续使用。

------

# 10. 模式分布建议

普通播放状态下：

- 低运动模式：约 55%；
- 中运动模式：约 30%；
- 电影化模式：约 12%；
- 特殊模式：不超过 3%。

丰富不等于一直运动。

如果每首歌都大幅飞行、旋转和推拉，三首之后就会疲劳。真正的变化来自静与动之间的对比。

## 五、最终判断

你的直觉是对的：只有少量镜头，RodiO 播放十首歌以后就会明显重复，无法支撑“宇宙电台”的长期沉浸感。

但解决方式不是简单堆预设，而是：

> 用十种构图、十四种运动原语和二十四种正式动态模式，建立一套能够根据音乐和真实宇宙状态组合的镜头语言。

第一批建议直接做 **12个模式**，系统结构一次搭对；最终日常模式库扩展到 **24个**，再加 **8个特殊模式**。这样丰富度足够，又不会让开发和后期调参彻底失控。
