## 1. E1 Day Earth Master 白天地图母版

### 1.1 目标

形成可长期复用的白天母版，而不是无限候选。

必须重点验收：

- 海洋层次：浅海、陆架、深海有层次；
- 太平洋岛屿：小岛周边浅海有可见领土感；
- 沙漠：中东、埃及、撒哈拉、澳洲内陆不过曝；
- 极地：南北极不刺眼，但极地过曝优先判定是否属于光照/大气问题；
- 重点海域：地中海、黑海、里海、日本海、南海、加勒比、红海、波斯湾；
- 陆地：山地、高原、森林、平原有差异，不能像教材地图，也不能过度卡通。

### 1.2 与 D5b / Bathy-3 的关系

D5b 仍然是白天母版的一个关键候选路径，但不再等同于整个 Earth 规划。

D5b 可以处理：

- bathymetry map 感；
- 浅深过渡偏硬；
- 全球浅海色调过于统一；
- 东亚近海改善有限；
- 热带浅海过度显性。

D5b 不处理：

- 夜晚海水；
- 城市灯光；
- 云层；
- 南极过曝；
- 整体贴图精度；
- 珊瑚礁 / 环礁精细化；
- 大气辉光。

完整 D5b 原始专项见本文件末尾“附录 E-A：Bathy-3 / D5b 原始全文”。

## 2. E2 Night Earth Master 夜晚地图母版

### 2.1 目标

夜晚版必须从白天母版派生，避免昼夜割裂。

夜晚不是“白天图压暗”，而是：

```text
低亮度地貌底图 + 暖色城市灯光 + 冷色海洋暗部 + 干净黑位
```

### 2.2 城市灯光设计

参考城市夜景的关键不是“灯多”，而是层次。

城市灯光应分三层：

| 层级 | 内容 | 视觉要求 |
|---|---|---|
| 一级亮点 | 超大城市核心 | 少量高亮，不能全局泛白 |
| 二级光带 | 城市群 / 沿海经济带 | 连续但克制 |
| 三级底光 | 普通城市 / 道路网络 | 背景肌理，不抢主体 |

色彩：

- 主体：暖黄、暖白；
- 核心高光：少量冷白；
- 暗部海洋：冷蓝黑；
- 禁止大面积霓虹紫、荧光蓝、纯白灯。

### 2.3 夜晚黑位

夜晚高级感来自黑位。海洋、山地、沙漠、无人区必须保持干净暗部。不要为了看清而把夜晚地表整体提亮。

## 4. E4 Cloud Layer 云层专项

云层在白天/夜晚母版之后处理。

原则：

1. 轻薄，不喧宾夺主；
2. 透明度低；
3. 运动极慢；
4. 白天略可见，夜晚极克制；
5. 不遮城市灯光；
6. 不加剧南极白化；
7. 不掩盖浅海层次；
8. 不做实时天气系统。

第一版只做 `Static / Slow Rotating Cloud Layer`，不做复杂动态云。

## 5. E5 Atmospheric Limb Glow 大气边缘辉光

### 5.1 命名

统一称为：

```text
地球边缘大气辉光 / atmospheric limb glow
```

### 5.2 当前问题

- 太均匀，像 UI 描边；
- 太宽，像雾带；
- 太蓝白，像滤镜；
- 过渡不自然；
- 夜晚过亮会破坏城市灯光氛围。

### 5.3 目标

不是“边缘发光”，而是“非常薄的大气在太阳照射下产生的真实散射感”。

要求：

- 更薄；
- 更轻；
- 有方向性；
- 与太阳方向/时间模式相关；
- 夜晚显著减弱；
- 避免 Bloom 过量。

# RodiO 3D 地球视觉优化近期推进规划

> 版本：v1.0  
> 时间锚点：2026-06-02  
> 范围：白天海洋 D5b、整体精度、云层、夜晚海水、光照与极地问题  
> 当前阶段：Bathy-3 收口 → D5b 白天海洋候选准备  
> 基本原则：分阶段推进、单变量验证、先审计后修改、先候选后替换、先验收后 commit。

---

## 0. 总体判断

当前 RodiO 3D 地球视觉优化已经进入从“路线验证”转向“视觉收敛”的阶段。

D5a 已经证明 bathymetry 路线有效：真实水深数据可以增强浅海、陆架和近岸水体层次，并且没有大范围破坏深海、陆地和冰雪。但 D5a 还不能定版，主要问题包括：

1. 热带浅海局部存在 bathymetry map 感；
2. 浅水与深水过渡偏硬；
3. 全球浅海色调过于统一；
4. 东亚近海改善有限；
5. 大堡礁、马尔代夫、环礁等细碎浅海表达不足；
6. 南极存在过曝感；
7. 深海整体信息量偏少；
8. 云层、夜晚海水、整体清晰度尚未系统审查。

后续不能把所有问题都塞进 D5b。D5b 只应作为“白天海洋 bathymetry 收敛候选”，解决 D5a 能解决的问题；夜晚、云层、精度、极地过曝、珊瑚礁精细化，应分别作为独立专项推进。

---

## 1. 推进总原则

### 1.1 单变量原则

每一轮只解决一类问题，避免同时修改贴图、光照、云层、夜晚参数和运行时代码。

错误做法：

- 同时生成 D5b；
- 同时改 `earth3d.js`；
- 同时调 cloudMesh；
- 同时改 atmosphere；
- 同时改 nightTexture；
- 同时提交 commit。

正确做法：

- 先生成候选；
- 上球对比；
- 固定地点验收；
- 确认问题归因；
- 再进入下一阶段。

### 1.2 候选优先原则

所有视觉资源都先作为候选文件存在，不得直接替换默认资源。

要求：

- 新贴图先放入 candidates 或 staging；
- 不直接覆盖稳定文件；
- 不自动改默认值；
- 不自动 commit；
- 先由人工截图验收。

### 1.3 阶段边界原则

D5b 只解决白天海洋问题，不解决：

- 夜晚海水；
- 城市灯光；
- 云层；
- 南极过曝；
- 整体贴图精度；
- 珊瑚礁 / 环礁精细化；
- 深海信息量不足。

这些问题进入后续专项。

### 1.4 验收先于优化原则

每次候选生成后，必须用固定地点做 A/B 测试，而不是凭单张截图判断。

固定测试工具：

```js
rodioGeoTest.go("地点名")
```

固定测试维度：

- D3；
- D5a；
- D5b；
- 必要时 D5b-extra。

# Phase 1：Bathy-3 收口

## 1.1 阶段目的

把 D5a 审计正式收口，明确：

1. D5a 哪些地方有效；
2. D5a 哪些地方有问题；
3. 哪些问题 D5b 可以解决；
4. 哪些问题不应在 D5b 解决；
5. D5b 的边界、目标和验收标准。

## 1.2 当前结论

D5a 的路线有效，但不能直接定版。

D5a 可以保留的方向：

- 浅海层次增强；
- 陆架表达增强；
- 波斯湾、北海、澳洲北部等区域改善明显；
- 深海基本未被破坏；
- 陆地与冰雪保护基本有效。

D5a 需要修正的问题：

- 热带浅海 map 感；
- 浅水 / 深水边界偏硬；
- 全局目标色过统一；
- 东亚近海色调与增强幅度仍不理想。

## 1.3 D5b 应解决的问题

D5b 只解决以下问题：

| 问题 | 修正方向 |
|---|---|
| bathymetry map 感 | 增大 blur，降低浅水权重 |
| 浅深过渡过硬 | depth field 平滑 + weight map 二次平滑 |
| 全球浅海色调过统一 | 调整目标色，减少统一青绿滤镜感 |
| 东亚近海改善有限 | 轻微区域补偿，偏灰蓝 / 泥灰方向 |
| 热带浅海过度显性 | saturation 钳制，降低浅水局部对比 |

## 1.4 D5b 不解决的问题

| 问题 | 不在 D5b 处理的原因 | 后续阶段 |
|---|---|---|
| 南极过曝 | D3 与 D5a 冰雪几乎无差异，属于光照 / 大气问题 | Phase 7 |
| 大堡礁 / 马尔代夫消失 | ETOPO1 分辨率不足，非简单参数可解 | Phase 8 |
| 太平洋深海信息量少 | 不应从 ETOPO1 引入深海地形纹理 | Phase 4 / 5 / 7 |
| 夜晚海水 | 属于 nightTexture / emissive / 夜间主题问题 | Phase 6 |
| 云层 | 独立视觉层，会影响海洋、极地、夜晚 | Phase 5 |
| 整体精度 | 涉及贴图压缩、采样、加载、设备性能 | Phase 4 |

# Phase 2：D5b 白天海洋候选

## 2.1 阶段目的

生成 D5a 的视觉收敛版。

D5b 不是新路线，也不是更强版本，而是更自然、更柔和、更适合上球的白天海洋候选。

## 2.2 D5b 核心目标

1. 保留 D5a 的浅海层次；
2. 降低 bathymetry map 感；
3. 缓和浅水 / 深水边界；
4. 避免全球浅海统一青绿色；
5. 东亚近海略增强但不变脏；
6. 热带浅海降低饱和与边界感；
7. 深海保持基本不动；
8. 陆地与冰雪继续完全保护。

## 2.3 D5b 参数方向

### 2.3.1 Weight 收敛

D5a 问题之一是浅水权重偏高。D5b 应降低浅水权重。

建议方向：

| 深度区间 | D5a | D5b 建议方向 | 目的 |
|---|---:|---:|---|
| 0–20m | 0.22 | 0.13–0.14 | 降低浅色贴片感 |
| 20–50m | 0.18 | 0.10–0.11 | 缓和浅水层次 |
| 50–200m | 0.12 | 0.08 | 保留陆架但不强化 |
| 200–1000m | 0.04–0.05 | 0.03 | 基本不动 |
| >1000m | 0–0.01 | 0 | 深海完全保护 |

### 2.3.2 Blur 增强

D5b 的核心不是单纯降权重，而是增强平滑。

建议方向：

| 参数 | D5a | D5b 建议 | 目的 |
|---|---:|---:|---|
| depth field sigma | 6 | 12 | 软化水深场 |
| weight map blur | 无 | 6–8 | 对权重再平滑 |
| 热带岛链额外 blur | 无 | 可选 +4 | 减少岛礁色圈 |

原则：

- 不要硬切分区；
- 不要让边界产生色带；
- 所有区域增强都应使用 soft mask。

### 2.3.3 目标色调整

D5a 的 very shallow 目标色存在 G > B 问题，容易让全球浅海向统一青绿色靠近。

D5b 应调整为更克制的蓝灰方向。

建议方向：

| 深度 | D5a 目标色 | D5b 建议方向 |
|---|---|---|
| 0–20m | 129 / 182 / 174 | 降 G，保持 B ≥ G |
| 20–50m | 113 / 170 / 178 | 降 G 与 B，保持蓝灰 |
| 50–200m | 96 / 147 / 157 | 轻微降低 |
| 200–1000m | 74 / 109 / 129 | 极轻微调整 |
| >1000m | 52 / 80 / 105 | 不使用，weight = 0 |

### 2.3.4 东亚近海轻微补偿

东亚近海可以做轻微区域补偿，但必须非常克制。

重点区域：

- 黄海；
- 渤海；
- 东海；
- 台湾海峡；
- 南海北部；
- 日本海；
- 白令海 / 鄂霍次克海可作为高纬近海参考。

目标：

- 更灰蓝；
- 稍微浑浊；
- 不变绿；
- 不变脏；
- 不形成蓝膜。

### 2.3.5 热带浅海限制

热带浅海需要降低人工感。

重点区域：

- 巴哈马；
- 加勒比；
- 菲律宾；
- 印尼；
- 大堡礁；
- 澳洲北部；
- 红海；
- 波斯湾。

目标：

- 保留浅海层次；
- 降低色圈感；
- 降低局部 bathymetry map 感；
- saturation 不得高于 D3；
- 不追求礁盘精细化。

## 2.4 D5b 禁止事项

D5b 阶段禁止：

# Phase 3：D5b 上球验收

## 3.1 阶段目的

判断 D5b 是否比 D5a 更适合成为白天贴图基线。

不是判断 D5b 是否“完美”，而是判断它是否：

1. 比 D3 更有浅海层次；
2. 比 D5a 更少人工感；
3. 没有破坏深海；
4. 没有误伤陆地与冰雪；
5. 没有引入新的区域色偏。

## 3.2 验收地点

### 东亚近海

```text
黄海中部
渤海
东海
台湾海峡
南海北部
日本海
菲律宾吕宋附近
台湾以东深水
```

看点：

- 是否比 D3 有层次；
- 是否比 D5a 更自然；
- 是否灰蓝但不脏；
- 是否避免过绿。

### 热带浅海

```text

加勒比
大堡礁
澳洲北部
菲律宾群岛
```

# Phase 4：Texture Fidelity Audit 整体精度审查

## 4.1 阶段目的

判断整体画面“不够高清、不够 iPhone 感”的真实原因。

这不是单纯白天海水问题，而是完整纹理链路问题。

## 4.2 审查重点

| 维度 | 审查内容 |
|---|---|
| 贴图分辨率 | 当前 8192 是否真实加载，是否有浏览器降采样 |
| 文件压缩 | JPEG 是否压缩过重，冰雪 / 深海 / 近海是否损失细节 |
| 纹理采样 | minFilter / magFilter / anisotropy 是否合理 |
| GPU 内存 | 移动端是否承受 8192，是否需要 fallback |
| 加载速度 | 首屏是否变慢，是否影响 PWA 体验 |
| 视觉锐度 | 远景、近景、边缘、海岸线是否清晰 |
| 大气 / 云层影响 | 是否是叠加层造成糊感 |

## 4.3 不应马上做的事

不要直接：

- 上 16K；
- 换 PNG；
- 换无损格式；
- 强行提高清晰度；
- 大幅增加资源体积；
- 牺牲移动端稳定性。

## 4.4 可能方向

| 方向 | 说明 |
|---|---|
| 8192 高质量 JPG | 优先检查压缩质量是否足够 |
| WebP / AVIF | 需要看浏览器支持和加载表现 |
| 桌面 8192 / 移动 4096 | 更现实的性能策略 |
| anisotropy | 可能改善斜视角贴图清晰度 |
| mipmap 设置 | 影响远景和过渡 |
| 纹理预加载 | 减少进入黑屏或延迟 |

## 4.5 阶段产物

建议报告：

```text
docs/devlog_texture_fidelity_audit.md
```

建议内容：

- 当前贴图尺寸与文件体积；
- 浏览器实际加载确认；
- 移动端风险；
- 是否需要多规格贴图；
- 是否建议调整纹理采样参数；
- 是否建议压缩格式试验。

# Phase 5：Cloud Layer Audit 云层专项

## 5.1 阶段目的

审查云层是否提升真实感，还是遮挡细节、制造糊感、加剧极地过曝或影响夜晚灯光。

云层不是装饰层，而是影响整体真实感的关键层。

## 5.2 审查重点

| 维度 | 看什么 |
|---|---|
| 云层透明度 | 是否太淡、太厚或遮挡浅海 |
| 云层精度 | 是否糊、块状、分辨率不足 |
| 云层颜色 | 是否过白、过灰、过蓝 |
| 云层分布 | 是否像真实云系，还是噪声贴图 |
| 云层运动 | 是否自然，是否速度过快 |
| 白天影响 | 是否增强大气感，还是削弱海洋细节 |
| 夜晚影响 | 是否遮挡城市灯光，是否夜晚太亮 |
| 极地影响 | 是否加剧南极白化 |
| 深海影响 | 是否能给深海增加低频层次 |

## 5.3 云层处理原则

1. 云层应辅助真实感，不应成为视觉主角；
2. 云层不能遮掉刚完成的 D5b 浅海层次；
3. 夜晚云层应比白天更克制；
4. 云层不能让南极更白；
5. 云层运动应慢，不应有廉价动效感；
6. 云层贴图质量应匹配地球底图。

## 5.4 阶段产物

建议报告：

```text
docs/devlog_cloud_layer_audit.md
```

可能候选资源：

```text
pwa/assets/earth/clouds/cloud_alpha_4096x2048_candidate_x.png
```

但云层专项开始前，不应在 D5b 阶段修改 cloudMesh。

| 极地夜晚 | 是否有异常白块 |
| 深空背景 | 是否与夜晚地球协调 |

## 优先级 4：夜晚海水专项

第四优先级是 Night Ocean Audit。

原因：

夜晚逻辑与白天不同，应在白天基线和云层状态相对稳定后单独处理。

## 优先级 5：光照 / 极地专项

第五优先级是 Atmosphere / Lighting / Polar Audit。

原因：

南极过曝已经确认不属于 D5a 贴图误伤，应在白天底图稳定后从光照和大气层角度处理。

大堡礁、马尔代夫、环礁精细化暂缓。

原因：

这不是 D5b 能低成本解决的问题，容易引入新资源、新 mask、新复杂度，风险高于当前收益。
