## v0.9 · 稳定性收口版

**目标：RodiO 不再莫名其妙断。只做四件事。**

**任务**

**1. 贴图压缩**（最优先，当前最卡的点）
- earth_day_8k.jpg：21600×10800 → 4096×2048
- earth_night_8k.jpg：13500×6750 → 4096×2048
- 验收：首屏等待 < 3 秒，控制台不再报 texture resize

**2. 播放链路稳定**
- NCM cookie 定时检测，失效自动续期
- 失效时静默降级到 Spotify，用户无感
- Spotify 429：确认 800ms 间隔是否足够，加指数退避重试
- 任何播放失败：自动重试一次，再失败跳下一首，不卡住

**3. 队列补充稳定**
- 队列空时 fallback 完善，用空 Set 触发补充
- 预加载下一首，切歌无 gap

**4. WebGL / 音频失败兜底**
- WebGL context lost：自动重建，不白屏
- 音频加载失败：自动跳下一首，记录日志

**不在 v0.9 做的事**
- 星星渲染修复 → 放 v1.1
- 天气主动感知 → 放 v1.2
- 任何视觉功能

**验收标准**
- [ ] 桌面网页连续播放 2 小时不中断
- [ ] 首屏 < 3 秒出现地球
- [ ] 控制台无 texture resize 报错
- [ ] 播放失败能自动恢复

**估算工期：2–3 周**

## v1.0 · 移动端可用版

**目标：手机上能稳定听音乐，PWA 可安装，锁屏界面正常。**

地球在这一版只需要"能跑、不发热"，不需要漂亮。

**任务**

**1. PWA 配置**
- manifest.json：图标、名称、standalone 模式、主题色
- Service Worker：静态资源缓存，离线时不崩溃
- HTTPS 确认（Railway 已有，确认证书正常）

**2. MediaSession API**
- 锁屏界面显示：歌名、歌手、专辑封面
- 绑定事件：播放、暂停、上一首、下一首
- 耳机按键可用

**3. 移动端播放器模式（低功耗地球）**
- 手机端默认进入播放器模式：15fps，低分辨率贴图（2048×1024）
- Page Visibility API：页面隐藏时暂停渲染，音乐继续
- 锁屏时：Three.js 暂停，音频线程继续
- devicePixelRatio 限制：`Math.min(window.devicePixelRatio, 1.5)`

**4. 响应式布局基础**
- 竖屏手机：播放器模式为主，地球缩小为背景
- 横屏/平板/桌面：地球为主，播放信息浮层
- 手势：向上滑动进入地球全屏模式，向下滑动退出

**PWA 验收测试矩阵**

| 测试项 | iOS Safari | iOS PWA | Android Chrome |
|--------|-----------|---------|---------------|
| 网页播放正常 | ✓ 验收 | ✓ 验收 | ✓ 验收 |
| 安装到主屏幕 | — | ✓ 验收 | ✓ 验收 |
| 锁屏当前歌曲继续 | ✓ 验收 | 观察项* | ✓ 验收 |
| 锁屏后自动下一首 | 观察项* | 观察项* | ✓ 验收 |
| 切到其他 App 不中断 | 观察项* | 观察项* | ✓ 验收 |
| 耳机暂停/继续 | ✓ 验收 | ✓ 验收 | ✓ 验收 |
| MediaSession 信息更新 | ✓ 验收 | ✓ 验收 | ✓ 验收 |
| 弱网自动 fallback | ✓ 验收 | ✓ 验收 | ✓ 验收 |

*观察项：记录表现，不作为强验收条件。iOS PWA 的后台限制是已知限制，接受它。

**验收标准**
- [ ] 手机安装到主屏幕，有独立图标，打开无地址栏
- [ ] 锁屏界面显示歌曲信息，可控制播放暂停
- [ ] 手机亮屏连续播放 1 小时不中断，不过热
- [ ] Android Chrome 自动下一首正常
- [ ] 竖屏布局可用，不错位

**估算工期：3–4 周**

## v1.1 · 3D 地球稳定版

**目标：地球成为 RodiO 的核心视觉资产，手机和桌面都能稳定运行。**

**任务**

**1. 分级贴图系统**
- 手机端：2048×1024（v0.9 压缩后的低清版）
- 桌面标准：4096×2048
- 懒加载：先低清，加载完成后无缝换高清
- KTX2 + Basis Universal 压缩格式（体积再减 70%）

**2. 星星渲染修复**
- 定位赤道坐标→地平坐标变换问题
- 修复后星星在正确位置，随时间缓慢移动
- 亮度随月相变化（月满时变暗）

**3. 夜景质感**
- 城市灯光不发灰、不糊：调整夜间纹理亮度对比度
- 城市灯光层次：商业区亮/居民区暖/路灯连线隐约可见
- 夜间贴图和星星之间不互相打架

**4. 大气层 + 云层统一**
- 大气层：边缘散射，克制，不过亮
- 云层：独立半透明球体，不遮挡城市灯光
- 三层（地球/云层/大气）z-index 和透明度参数整理清楚

**5. WebGL fallback 完善**
- WebGL 不可用：显示静态天空背景，不崩溃，不暴露错误
- fallback 时播放功能完全正常

**6. 视觉参数配置化**
- 所有视觉参数抽成配置表
- 为后续九段时光、节气、节日打好叠加接口
- 不再靠手调参数

**7. 手机端性能验收**
- iPhone 12+：播放器模式流畅（>30fps），全屏模式可用（>20fps）
- Android 中端机：播放器模式流畅
- 连续使用 30 分钟不过热

**验收标准**
- [ ] 首屏手机端 < 3 秒，桌面 < 5 秒
- [ ] 星星位置正确，随时间移动
- [ ] 夜晚城市灯光有层次感，不发灰
- [ ] 手机 30 分钟不过热
- [ ] 视觉参数全部配置化

**估算工期：4–5 周**

## v1.2 · 此刻系统版

**目标：RodiO 知道现在是几点、外面是什么天气、今天的太阳在哪里。**

**任务**

**1. 九段时光系统**
- 接入 SunCalc，基于用户真实经纬度计算日出日落
- 九段边界由真实太阳时决定，不用行政时区
- 新疆和福建的清晨时间不同，RodiO 知道
- 每段有独立的天空渐变参数（配置表）

**2. 天气主动感知**
- 接入彩云天气 API（分钟级降水，国内）
- 前台：10 分钟更新一次
- 后台：暂停天气轮询
- 重新打开页面：立即刷新一次
- 天气状态未变化：不触发视觉更新

**3. 天气 × 时段视觉矩阵（基础版）**
- 晴/多云/雨/雪 × 九段时光
- 雨分两档：毛毛雨（空气模糊）和中雨（清晰雨帘）
- 落日类型由云量决定：纯净落日/火烧云/隐没型
- 雨后 30 分钟洗净感

**4. 天气变化响应链**
- 感知到天气变化 → 视觉层开始悄悄偏移
- 当前歌播完 → 下一首选曲情绪随天气调整
- 不硬切，不打断当前歌曲

**验收标准**
- [ ] 九段时光随真实太阳时正确切换
- [ ] 上海和乌鲁木齐的清晨时间不同
- [ ] 天气变化能被感知，视觉有响应
- [ ] 落日类型与实际云量对应

**估算工期：3–4 周**

## v1.3 · 天外来信版

**目标：每首歌开始时，有一封信从天外降临，说了一句话，然后离去。**

**任务**

**1. 来信生成架构**

分层设计，控制成本和延迟：

- 普通时刻：模板库 + 变量填充（时段/天气/月相）
  - 示例模板："{时段}。{天气描述}。{歌手}写这段旋律的时候，{情景联想}。"
  - 约 50 个模板，覆盖常见组合
  - 本地生成，零延迟，零成本

- 特殊时刻（节气当天/稀有天气/节日）：Qwen API 生成
  - 注入 context：时段 + 天气 + 月相 + 节气 + 节日 + 歌曲信息
  - 约 500–800 tokens/次

- 用户祈求/高价值时刻：Claude API 生成
  - 注入更完整 context，包括祈求内容
  - 约 1000–2000 tokens/次

- 预生成策略：当前歌曲播放中就生成下一首的来信，不让用户等待

**2. 来信出现与消失动画（基础版）**
- 出现：凝结效果（整段文字从无到有，不是逐字打出）
- 存在：十秒，极微弱漂浮
- 消失：离散效果（向上扩散）
- 两个界面模式都显示

**3. 来信历史（基础版）**
- 本地存储（localStorage）
- 极简列表：时间 + 来信文字，没有歌曲信息
- 默认保留最近 30 天
- 可以导出为文本

**验收标准**
- [ ] 每首歌开始有来信出现
- [ ] 出现和消失有动画，不是突然闪现
- [ ] 来信语言符合 RodiO 气质，不像 AI 生成的说明书
- [ ] 来信历史可查看，可导出

**估算工期：3–4 周**

## v1.4 · 文化时间层

**目标：RodiO 有时间信仰和文化气质。**

**任务**

**1. 七曜系统**
- 纯本地计算
- 零点交接仪式：23:50 当前曜日天体隐退，00:00 新天体出现
- 整个过程 2–3 分钟，克制，不张扬
- 零点来信特殊模板："子时。日离去，月接手。"
- 周日→周一略有不同处理

**2. 二十四节气（隐形调度器）**
- 基于太阳黄经本地计算
- 不弹窗，不宣告
- 每个节气影响：天空色温偏移、雨雪概率权重、风速感
- 七十二候词库：供来信语言使用

**3. 主节日系统**
- lunar-javascript 处理农历转换
- 主节日：春节、元宵、清明、端午、七夕、中元、中秋、重阳、冬至、腊八、除夕
- 每个节日有视觉参数和来信模板
- 春节整点烟花（Canvas 叠加层）
- 中秋：月亮稍大稍暖
- 冬至来信："冬。"

**4. 扩展节日（轻量氛围）**
- 立春、花朝、龙抬头、上巳、佛诞、寒衣、下元、尾牙、圣诞、世界地球日
- 只影响来信语气和少量视觉参数，不做完整视觉主题

**5. 地域权重**
- 用户地理位置影响节日强度
- 尾牙：闽台用户主节日，北方用户轻彩蛋
- 圣诞：热带地区雪的视觉更克制

**6. 三层叠加引擎**
- 七曜 × 节气 × 天气，计算叠加分数
- 分数影响来信模板选择和视觉参数偏移
- 不向用户暴露任何标签或提示

**验收标准**
- [ ] 零点交接动画正确触发
- [ ] 节气参数影响视觉，但用户说不清为什么
- [ ] 主节日视觉和来信正确
- [ ] 地域权重生效

**估算工期：4–5 周**

## v2.0 · 陪伴与空间扩展版

**目标：RodiO 从"此刻"扩展到"陪伴"和"世界"。**

等前面都稳了再做。任务按优先级排序，可以拆开分批。

**陪伴层**

1. **祈求系统**
   - "此刻"界面完整功能
   - 用户写状态，系统收到，无确认反馈
   - 当前歌播完，下一首响应祈求
   - Claude API 处理：解析情绪 + 影响选曲 + 生成来信
   - 回应不直接引用，只是语气隐隐呼应

2. **记忆层（合规优先）**
   - 默认关闭，用户明确开启
   - 告知用户存什么：时间戳 + 天气状态 + 情绪摘要（不存原文）
   - 支持删除、导出
   - 本地优先存储，云端可选
   - 来信历史和祈求记忆分开

3. **"飞去某个地方"**
   - 写地名，Mapbox Geocoding 解析
   - 地球转到那里，停下
   - 来信告诉你那里此刻的状态
   - 选曲情绪来自那个地方

4. **分享卡**
   - Canvas 截图：宇宙视觉 + 来信文字
   - 无 logo，无链接，导出 PNG

**空间扩展层**

5. **彩蛋库**
   - 彩蛋规则 JSON 数据库
   - A类歌词意象：约 30 条
   - B类情绪反差：约 10 条
   - C类歌手专属：约 20 条
   - D类BPM/风格：Spotify Audio Features API 自动触发
   - E类特殊时刻：基于时间和行为
   - F类极罕见：天文事件触发

6. **地球三维旋转**
   - 左右转：穿越时区，晨昏线移动
   - 上下转：穿越纬度，极地极昼极夜
   - 地球的另一面：偶尔来信提及对跖点

7. **潮汐层**
   - WorldTides API（免费额度 1000 次/月）
   - 沿海 50km 内用户启用
   - 潮位影响水面颜色和地平线高低

8. **光污染层**
   - Light Pollution Map 离线数据
   - 星星密度随光污染等级调整
   - 城市用户深夜天空有橙黄底色

9. **声音层**
   - 环境音素材库：雨声/虫鸣/风声
   - 始终保持音乐音量的 3–8%
   - 雪天用声音的缺席表达静默

10. **飞行模式**
    - 位移检测：1 小时内 > 500km
    - 高空天空色，云层在下方
    - 来信："三万英尺。云在脚下。"

11. **稀有天文事件**
    - 日食/月食：视觉特殊处理
    - 流星雨：极大期频率提升
    - 极光：高纬度用户 Kp 达标时出现

**估算工期：8–12 周（按功能拆开，分批做）**

| iOS PWA 锁屏后续播不稳定 | 接受限制，记录为已知问题，告知用户；用户量大了再考虑原生 |
| Three.js 手机端性能不足 | 双模式渲染，播放器模式 15fps，全屏才全力跑 |
| Claude API 来信延迟 > 3 秒 | 预生成：当前歌播放中生成下一首来信，提前缓存 |
| NCM cookie 持续过期 | v0.9 优先解决自动续期 |
| 同一问题反复超过两次 | 必须质疑技术路线本身，不继续打补丁 |
| 开放用户后 API 成本超预期 | 服务端缓存天气，模板库覆盖普通来信，控制 Claude API 调用频率 |
