# RodiO 地球日间贴图配色工程执行方案

## 主题：Noon Air Earth / 正午空气蓝地球

## 文档定位

本文件不是图像生成提示词，而是用于 Claude Code / Codex / Cursor 等代码型 AI 执行的 **地球日间贴图调色工程规范**。

适用对象：

```text
1. RodiO 项目中的日间地球贴图。
2. 基于 Python / Pillow / NumPy / OpenCV 的图像处理脚本。
3. Three.js 地球材质加载前的静态贴图候选图生成。
```

不适用对象：

```text
1. Midjourney / DALL·E / Stable Diffusion 等纯文生图工具。
2. 从零生成地球图。
3. 不具备地理分区处理能力的通用修图工具。
```

核心原则：

```text
先审计，后脚本；
先候选图，后前端替换；
先局部 preview，后整体判断；
不得直接覆盖原始贴图；
不得直接 push 到线上环境。
```

---

# 0. 总体目标

本方案用于调整 RodiO 日间地球贴图，不修改 UI，不修改夜景，不修改云层。目标是在保持真实地理识别度的基础上，形成清透、明亮、克制、具有高空正午低轨道视角的审美化地球质感。

整体观感应接近：

```text
冷调正午蓝 + 清透深海 + 克制浅海青蓝 + 低饱和陆地 + 暖沙色沙漠 + 蓝白冰原
```

总体原则：

```text
深海要清澈，不要黑。
浅海要发光，但不要荧光。
陆地要低饱和，不要地图绿。
沙漠要暖，但不要过曝。
冰原要蓝白有纹理，不要死白。
群岛要有浅海光晕，不要只剩小点。
大气要轻薄，不要灰雾糊图。
```

禁止方向：

```text
禁止 NASA 黑蓝高对比风格。
禁止 Google Earth 原始卫星硬对比风格。
禁止游戏地图式高饱和绿蓝。
禁止复古地图黄褐色。
禁止全图灰化、脏化、暗化。
禁止牺牲真实地理识别度来追求统一色调。
```

# 1. 工程执行总流程

## 1.1 第一阶段：资产审计，不直接动图

先让 Claude Code 扫描当前项目，确认实际加载逻辑和贴图资产。不得直接修改图片或代码。

给 Claude Code 的指令：

```text
请扫描当前项目，找到以下内容并输出清单：

1. Three.js 中实际加载 day texture 的代码位置和文件路径；
2. 当前前端实际使用的日间贴图文件名和分辨率；
3. pwa/assets 目录下所有贴图文件的名称、大小、分辨率；
4. 是否存在候选图切换逻辑；
5. 是否存在 candidates 目录；
6. 是否存在已有的图像处理脚本；
7. 是否存在与 D5b、D5c、D5y、GEBCO、GSHHG、DEM、OSM、VIIRS 相关的数据或脚本。

要求：
- 不要修改任何文件；
- 不要生成新图片；
- 只输出清单；
- 对当前实际加载路径与候选图路径分别说明。
```

输出后人工确认：

```text
1. 哪张是当前前端实际加载图；
2. 哪张是目标源图；
3. 候选图应保存到哪个目录；
4. 是否需要新增 candidates 目录；
5. 是否需要临时切换前端候选图。
```

---

## 1.2 第二阶段：生成调色脚本，不覆盖原图

确认源图后，再让 Claude Code 生成 Python 调色脚本。

给 Claude Code 的指令模板：

```text
请基于以下规范，用 Python 编写一个地球贴图调色脚本。

技术要求：
- 使用 Pillow + NumPy；
- 可选使用 OpenCV，但不得作为强依赖；
- 输入文件：[人工确认后的源图路径]；
- 输出文件：earth_day_noon_air_v1.jpg；
- 输出目录：源图同级 candidates 文件夹；
- 不覆盖原文件；
- 如果 candidates 文件夹不存在，则创建；
- 输出一张 1/4 分辨率全局预览图；
- 输出关键区域 before/after 对比图；
- 每个区域处理完成后输出 log；
- 脚本应分步骤写，不要一个函数塞所有逻辑；
- 脚本应支持 dry-run / preview-only 模式；
- 脚本运行失败时不得删除或覆盖任何现有文件。

处理方式：
- 用经纬度范围建立区域 mask；
- 不得全局粗暴套滤镜；
- 不得直接用目标 HEX 色值替换像素；
- 目标色值是调色趋近参考，应通过 HSL 调整、曲线调整、颜色混合、局部梯度映射等方式保留原始纹理；
- 处理时必须保留地形、海底、冰川、沙漠纹理和海岸线结构。
```

---

脚本跑完后，不要立刻替换前端运行图。先生成以下区域 before/after 对比图。

给 Claude Code 的指令：

```text
请从处理前后的两张贴图中，按经纬度裁切以下区域，并输出 before/after 对比图：

1. 马尔代夫：经度 72 到 74，纬度 -1 到 8；
2. 巴哈马：经度 -80 到 -72，纬度 22 到 28；
3. 南极：经度 -180 到 180，纬度 -90 到 -70；
4. 格陵兰：经度 -55 到 -15，纬度 60 到 84；
5. 黄海东海：经度 118 到 130，纬度 25 到 38；
6. 撒哈拉：经度 -10 到 35，纬度 15 到 30；
7. 法属波利尼西亚：经度 -155 到 -135，纬度 -25 到 -10；
8. 夏威夷：经度 -162 到 -154，纬度 18 到 23；
9. 青藏高原：经度 75 到 100，纬度 27 到 38；
10. 亚马逊：经度 -75 到 -45，纬度 -15 到 5；
11. 地中海：经度 -6 到 36，纬度 30 到 46；
12. 红海：经度 32 到 44，纬度 12 到 30。

要求：
- 每张图包含处理前、处理后、差异图；
- 文件名包含区域英文名；
- 不修改前端引用；
- 不覆盖源图。
```

---

## 1.4 第四阶段：Three.js 本地实机验收

Python 输出的颜色，上 Three.js 球体后会因材质、光照、色彩空间、tone mapping、texture encoding 产生偏移。因此必须进行本地实机验收。

要求：

```text
1. 先在本地 Three.js 环境临时切换候选图；
2. 不要直接 push 到 Railway；
3. 不要直接替换线上 day texture；
4. 检查 noon / afternoon / morning 等主题下的实际球体效果；
5. 重点观察海洋是否过暗、浅海是否过亮、冰原是否死白、沙漠是否过曝；
6. 若 Three.js 中偏暗，应优先微调材质和光照，再决定是否回调贴图；
7. 若 Three.js 中偏灰，应先检查 colorSpace / encoding / toneMapping，不要立刻提高贴图饱和度。
```

# 3. 色彩空间与处理约束

## 3.1 色彩空间

默认要求：

```text
输入：sRGB
处理：NumPy RGB 数组
输出：sRGB JPEG 或 PNG
```

注意：

```text
1. 如果 Three.js 使用 SRGBColorSpace，应确保贴图保存为标准 sRGB。
2. 如果项目使用 LinearSRGBColorSpace 或 legacy encoding，应在审计阶段列明。
3. 不要在未知 colorSpace 情况下过度提高亮度或饱和度。
```

## 3.2 目标色值不是直接替换值

必须明确：

```text
所有 HEX 色值均为目标色阶参考，不是直接像素替换值。

执行时应采用：
- 颜色趋近；
- HSL 调整；
- 曲线调整；
- 局部混合；
- 梯度映射；
- mask 权重渐变。

目标是在保留原始纹理的基础上，让区域颜色向目标色阶靠近。
```

禁止：

```text
禁止把区域内所有像素直接替换成单一 HEX 色。
禁止破坏海底纹理、冰盖纹理、沙漠纹理、山体阴影。
禁止让区域边界出现硬切。
```

# 4. 区域 Mask 策略

## 4.1 区域识别优先级

```text
第一优先级：
使用已有地理遮罩、海陆遮罩、冰雪遮罩、DEM、GEBCO、GSHHG、OSM 等数据生成区域 mask。

第二优先级：
若暂无完整 mask，可使用经纬度 bbox 建立粗分区 mask，再结合颜色、亮度、海陆边界进行局部细化。

第三优先级：
仅在局部小范围内使用颜色阈值辅助处理。

禁止：
不得仅凭全局颜色阈值处理全部区域，避免把浅色沙漠误判为冰雪，把浅海误判为云或冰。
```

## 4.2 经纬度到像素映射

若输入为 equirectangular 2:1 贴图，可采用：

```text
x = (lon + 180) / 360 * width
y = (90 - lat) / 180 * height
```

其中：

```text
lon：经度，范围 -180 到 180
lat：纬度，范围 -90 到 90
width：贴图宽度
height：贴图高度
```

裁切 bbox 时注意：

```text
1. 经度跨越 -180 / 180 的区域需要特殊处理；
2. 纬度越高，视觉面积变形越明显；
3. 极地区域不要只按矩形处理，应结合冰雪颜色和海陆边界细化。
```

# 5. 分辨率自适应规则

## 5.1 小岛浅海环尺度

原“1 至 4 像素浅海环”需按分辨率自适应。

建议：

```text
8K 贴图（8192×4096）：
- 视觉浅海环约 1 至 4 px。

16K 贴图：
- 视觉浅海环约 2 至 8 px。

21.6K 贴图（21600×10800）：
- 视觉浅海环约 3 至 12 px。

实际宽度：
- 以地球视角可见但不发光为准；
- 不得形成明显描边；
- 不得把小岛处理成发光点。
```

## 5.2 Mask 羽化尺度

建议：

```text
8K：
- 小区域羽化 2 至 8 px；
- 大区域羽化 16 至 48 px。

21.6K：
- 小区域羽化 6 至 24 px；
- 大区域羽化 40 至 120 px。
```

原则：

```text
浅海、岛屿、冰缘必须柔化；
沙漠、森林、高原边界也要柔化；
禁止硬边色块。
```

# 6. 全局色彩控制

## 6.1 全局基础参数

建议作为最终调色前的基准控制，不建议一开始全局暴力套滤镜。

```text
全图亮度：+3% 至 +6%
全图对比度：-3% 至 -6%
全图饱和度：-4% 至 -8%
蓝色通道亮度：+4% 至 +8%
绿色饱和度：-8% 至 -15%
黄色饱和度：-5% 至 -12%
```

执行目的：

```text
1. 降低传统卫星图的硬对比。
2. 避免绿色、沙漠黄色过艳。
3. 保持海洋清透感。
4. 让地球更接近低轨道正午视角，而不是平面地图。
```

## 6.2 全局空气蓝叠层

最终可增加极轻的冷蓝空气感，但必须非常克制。

```text
叠加颜色：#8FC4E6
优先混合模式：soft light
默认透明度：4% 至 6%
最大透明度：不得超过 8%
```

限制：

```text
1. 优先使用 soft light。
2. 仅在整体过暗时局部使用 screen。
3. screen 不得用于冰原、沙漠和浅海高光区域。
4. 不得使用 10% 作为常规透明度。
5. 不要让陆地发灰。
6. 不要让沙漠变脏。
7. 不要让极地失去纹理。
8. 不要让整张图像蒙了一层厚蓝雾。
```

# 7. 海洋系统配色

海洋是 RodiO 地球的主视觉基础。必须形成“深海—中海—大陆架—近岸浅海—礁盘”的连续层次。

## 7.1 深海

适用区域：

```text
太平洋深海、大西洋深海、印度洋深海、南大洋深海、远离大陆架的海盆区域。
```

目标效果：

```text
清澈深蓝，有厚度，但不接近黑色。
```

推荐色阶：

| 类型 | 色值 | 用途 |
|---|---:|---|
| 最深海沟 | `#03243F` | 海沟、极深海暗部 |
| 深海主体 | `#05395F` | 大面积深海主色 |
| 中深海 | `#07527A` | 深海向中海过渡 |
| 受光远海 | `#126B92` | 海面受光区、高空远景 |
| 远景雾化海面 | `#3E8DB0` | 接近地平线的大气淡化区域 |

执行要求：

```text
1. 最深海区域允许接近 #03243F，但不能低于该亮度。
2. 大面积深海主体应控制在 #05395F 到 #07527A。
3. 海面高光和远景区域可轻微提升到 #126B92。
4. 不能出现纯黑、墨蓝、灰蓝。
5. 深海纹理可以保留，但不要让海底沟壑变成黑色裂缝。
```

## 7.2 中浅海 / 大陆架

适用区域：

```text
黄海、东海、南海北部、波斯湾、红海、地中海近岸、加勒比海外围、澳大利亚大陆架、北海、波罗的海。
```

目标效果：

```text
比深海更亮，带青蓝过渡，体现大陆架浅水区。
```

推荐色阶：

| 类型 | 色值 | 用途 |
|---|---:|---|
| 大陆架深蓝 | `#0A5F84` | 深海向大陆架过渡 |
| 大陆架主色 | `#197FA0` | 大陆架主体 |
| 浅水过渡 | `#2FAAC0` | 近岸浅海 |
| 明亮浅水 | `#53C8D1` | 少量浅水高光 |

执行要求：

```text
1. 大陆架边缘必须有渐变，不允许深海直接切到浅海。
2. 近岸水域应从 #197FA0 过渡到 #2FAAC0。
3. 浅水高光只允许局部出现，不要铺满整片海域。
4. 黄海、渤海可以稍微灰一点，但不能浑浊发黄。
5. 地中海、爱琴海、加勒比可以更清透。
```

# 8. 群岛与礁盘配色

群岛必须单独处理。群岛不能只是陆地小点，而应当形成：

```text
岛屿核心 + 沙滩边缘 + 浅海环 + 礁盘高光 + 外海过渡
```

## 8.1 热带群岛通用规范

适用区域：

```text
马尔代夫、塞舌尔、巴哈马、加勒比小安的列斯群岛、斐济、汤加、萨摩亚、法属波利尼西亚、库克群岛、密克罗尼西亚、帕劳、所罗门、瓦努阿图、印尼东部群岛、菲律宾中南部群岛。
```

目标效果：

```text
小岛周围有清晰但克制的青蓝浅海光晕，能在地球视角中被识别。
```

推荐结构：

| 层级 | 色值 | 用途 |
|---|---:|---|
| 岛屿陆地核心 | `#4D7A56` 至 `#6E8F63` | 小岛植被 |
| 火山岛暗绿 | `#355F43` | 夏威夷、塔希提等高岛 |
| 沙滩边缘 | `#D8C99D` | 极窄岸线 |
| 极浅水 | `#A9EFEA` | 最浅水高光 |
| 礁盘青蓝 | `#5FD3D8` | 环礁、珊瑚礁 |
| 浅海主色 | `#2FAAC0` | 岛屿周边浅海 |
| 外海过渡 | `#197FA0` | 浅海向深海过渡 |
| 深海外缘 | `#07527A` | 外围深海 |

执行规则：

```text
1. 每个热带小岛周边应保留分辨率自适应的浅海青蓝环。
2. 浅海环不能是纯白，不能是荧光青。
3. 礁盘高光 #A9EFEA 只能用于最浅水区，面积不超过该岛周边浅海区域的 15%。
4. 岛屿陆地不能过黑，应保持低饱和绿色或灰绿色。
5. 小岛边缘不允许被深海蓝直接吞没。
6. 群岛密集区域应形成细碎的青蓝层次，而不是一整片亮蓝色块。
```

## 8.2 巴哈马 / 加勒比浅滩

```text

3. 生成 Python 调色脚本。
4. 先锁定深海色阶。
5. 再单独增强浅海与群岛。

7. 再压低沙漠高光。
8. 再降低陆地绿色饱和度。
9. 最后加极轻空气蓝统一画面。

11. 输出关键区域 before/after 对比图。

```
