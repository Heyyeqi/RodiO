> 关联：#52（太阳/月亮/自转/公转）、#53（五行星）
> 状态：RW看过`planets_deepspace.png`后反馈"不精致"，并给出三条具体规则，本文档回应
> 触发：2026-07-20

## 0. 诊断：不精致不只是审美问题，是一个真实的几何bug

用数字验证了一遍——`MOON_DIST=3`（月亮距地心3个场景单位）配合"恒定角直径缩放"（月亮渲染角直径固定4.5×真实值，不管相机多远都保持这个视角大小），在相机拉远到一定距离后，**月亮球体会几何穿透进地球球体内部**：

| 相机距地心 | 月亮渲染半径 | 月亮近边缘距地心 | 地球半径 | 结果 |
|---|---|---|---|---|
| 25.15（farOrbit） | 0.45 | 2.55 | 2 | OK，但只有0.55单位余量，视觉上确实贴得紧 |
| 40 | 0.75 | 2.25 | 2 | OK，余量更小 |
| 60 | 1.16 | 1.84 | 2 | ⚠️ 几何重叠 |
| 80（deepSpace） | 1.57 | 1.43 | 2 | ⚠️ 明显穿透地球表面0.57个单位 |

**根因**：恒定角直径缩放的物理前提是"观测者始终在地球附近"（月亮在天空中看起来多大，不随你在地球周围挪动而变化，这是真实天文事实）。但一旦相机本身拉远到deepSpace（80单位），相机自己变成了"远处的太空观测者"，这时候月亮应该跟着地球一起在视野里缩小比例，而不是保持"贴地观测"时的角直径——这个设计假设在#52定的时候只验证过farOrbit这一个距离，没验证deepSpace，是我brief的疏漏。

**这正好被RW的规则③自然修复**：如果月亮压根不在deepSpace出现（跟行星不同框），这个重叠bug就不会被触发。所以规则③不只是审美要求，也是在堵一个真实的渲染缺陷。

## 1. 叙事分层：相机拉远时天体依次登场/退场

不再用"一个连续距离变量决定所有天体开关"，改成三个有清晰边界的场景状态：

```
[近景 11.7~15.9]         [Moon Only ~25]      [Moon + Sun ~40]      [Sun + Planets, No Moon 80]
    地球本体                地球 + 月亮           地球 + 月亮 + 太阳       地球 + 太阳 + 五行星
    （现状不变）            月亮有真实轨道感        月亮与太阳共存           月亮消失，行星登场
```

### 1.1 三个状态的边界（初步提案，需要审计脚本核实，不是最终数字）

- **Moon Only**：`MOON_VISIBLE_DIST(20) ≤ d < MOON_SUN_TRANSITION(约35)`。只有月亮，没有太阳没有行星。这一段月亮是唯一的视觉焦点，应该给它足够的画面空间和轨道感。
- **Moon + Sun**：`MOON_SUN_TRANSITION(35) ≤ d < PLANETS_VISIBLE_DIST(50)`。太阳加入，月亮还在。这一段需要**新增一档相机构图**才能让用户实际导航到（现在farOrbit=25.15和deepSpace=80之间是空的，没有任何构图落在这个区间）。
- **Sun + Planets, No Moon**：`d ≥ PLANETS_VISIBLE_DIST(50)`，即deepSpace。月亮`visible=false`，太阳+五（后续八）颗行星+公转环。

### 1.2 新增相机构图的问题（需要RW确认）

现在`CAMERA_COMPOSITIONS`里只有`farOrbit`(25.15)和`deepSpace`(80)两档能到"看得到天体"的远景，中间完全是空的。要让用户能实际用手势/UI导航到"Moon+Sun"这个中间态，需要在`earth3d.js`的`CAMERA_COMPOSITIONS`里新增一档（比如叫`moonSunView`或类似名字），`earthDiameterPct`介于farOrbit(0.32)和deepSpace(纯cameraOffsetZ模式)之间。这不是"只改`real-celestial.js`"能解决的，需要动主构图库——按Category A/B分级，这属于"编排已验证的构图原语"（新增一个构图条目，不改变相机-几何体的基础关系），应该是Category A，风险可控，但需要RW确认要不要加这一档，还是先只做"Moon Only"和"Sun+Planets"两档，中间态先不急着让用户能导航到（只在deepSpace/farOrbit两个已有构图上做好月亮/太阳/行星的正确显隐，"Moon+Sun"这个中间叙事阶段可以先跳过，等以后有明确导航需求再补相机构图）。

**我的建议**：先做两档（Moon Only在farOrbit、Sun+Planets在deepSpace），不新增相机构图——这是最小改动、风险最低的路径，能立刻解决"不精致"和"月亮跟行星同框"这两个问题。"Moon+Sun"中间态列为后续可选项，不阻塞这一轮。

## 2. 月亮距离与呈现方式重新设计

### 2.1 距离：给出更宽裕的轨道感

`MOON_DIST`从3（1.5倍地球半径）提到**6（3倍地球半径）**——刚好等于当前`SUN_DIST`原来的孤立常数值（巧合，但也说明"3倍地球半径"是一个已经被验证过、看起来舒适的量级）。在farOrbit(25.15)距离下重新验证：

```
月亮渲染半径 ≈ (25.15-6) × tan(1.165°) ≈ 0.39
月亮近边缘距地心 ≈ 6 - 0.39 = 5.61，远大于地球半径2 → 有明显分离的空间感
```

### 2.2 恒定角直径倍数是否要跟着调整

现在4.5×真实角直径是之前审计过的"3-6倍"区间内的值，不建议这次跟着改——问题的根源是"距离太近"，不是"角直径倍数不对"。距离拉开之后，在同等倍数下月亮会显得更"悬浮"、更有空间感，不需要再动这个参数。

### 2.3 月亮场景专属的呈现细节（可选加分项，非必须）

RW说"月亮和地球的场景需要专门设计"，这里列几个可以在Moon Only这一档单独做的加分项（具体要不要做、做到什么程度，需要RW看过基础版本后再定）：
- 月亮公转轨迹的淡淡轨道线（跟地球绕太阳的公转环是同一视觉语言，但半径小很多，更贴近地球）
- 月相的更明显呈现（现在月相shader已经做了，但距离太近时看不清楚，拉开距离后应该会更清楚地看到明暗交界线）
- 是否需要给月亮加一点点自转/公转的缓慢动画（不是这次的范围，标注为可选）

## 3. 视觉精致度：现在的问题具体在哪

看`planets_deepspace.png`这张图，除了月亮穿透地球这个几何bug，还有几个可能拉低精致感的点，供参考：

1. **所有天体用的是同一种简单4档径向渐变canvas贴图**（太阳、五颗行星、包括早期的月亮光晕都是同一个`makeSunGlowTexture`/`makePlanetGlowTexture`模式）——视觉上区分度主要靠颜色和大小，缺少"这是恒星"vs"这是行星"的呈现差异（比如太阳理论上应该有更强的光芒感/日冕感，行星应该更收敛、更像一个干净的光点，不需要那么强的辉光扩散）。
2. **公转环是纯几何线框圈**（`THREE.LineLoop`），没有任何渐隐/透明度渐变处理，可能显得比较"工具感"，跟地球/月亮的真实材质质感不在一个精致度量级上。
3. **整体画面偏空旷**——deepSpace构图下，天体都挤在画面中心一小块区域，周围是大片纯黑（星空背景在这个视角下几乎不可见/权重很低），可能让人觉得"没有认真设计过构图"，而不是有意为之的留白。

这几点我没有把握说哪个是"不精致"的主因，需要看RW觉得具体是哪里别扭，再决定要不要在这一轮一起处理，还是列到后续打磨阶段。
