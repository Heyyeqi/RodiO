# RodiO D5a / D5b / D5c 上球差异不明显原因审计

**日期：** 2026-06-02  
**范围：** 仅审计 D5a / D5b / D5c 在地球球面渲染后的可见差异削弱原因  
**约束：** 不修改贴图、不改 `earth3d.js`、不改 atmosphere / cloud / lights / UI

---

## 结论摘要

- **源贴图层面有差异，但差异主要集中在浅海与近岸细节，强度偏小。**
- **上球后差异被主题灯光、天空/大气层、云层半透明叠加和整体 sRGB 输出压缩。**
- **D5c 相比 D5b 的增量，更多是局部海区的细微收敛，不是能在东亚主视角一眼看出的“强视觉跃迁”。**
- **下一步优先级应是 Texture Fidelity + Atmosphere/Cloud 视觉审计，而不是继续 D5d 调色。**
- **建议暂停 D5d。D5c 可以保留为候选，但暂不定版。**

---

## 1. D5a / D5b / D5c 在源贴图层是否有足够差异？

### 判断

有差异，但**差异强度不足以保证上球后肉眼明显分离**。

### 依据

- D5b 相比 D5a 的调整主要是近岸和浅海的 RGB / 权重收敛，目标是更自然的 bathy tint，而不是大幅改色。
- D5c / v6.1 继续在浅海区域做微调，并显式关闭了 turbidity 和 abyss/deep 的额外增强。
- 文档中的 zone metrics 显示，D5c 相比 D5b 的改动多为：
  - 近岸浅海区的 **1 到 4 级 RGB 小幅偏移**
  - 饱和度的小幅变化
  - 深海区域基本不变
- 这意味着 D5c 的“改良收益”主要发生在局部海岸带，而不是东亚主视角下最容易被观看到的大片海面。

### 审计判断

- **D5a -> D5b：** 有可见收益，尤其在浅海结构、色温和海区分层上。
- **D5b -> D5c：** 变化更细，属于“二次抠细节”，不是“视觉级升级”。
- 因此，**源层差异是存在的，但并不强到足以在上球后自然跳出来。**

---

## 2. 为什么浏览器中肉眼差异很弱？

### 主因 1: 贴图差异本身就集中在低对比区域

- D5b / D5c 的差异主要在浅海、陆架、局部海湾。
- 在东亚主视角中，真正占视觉主导的往往是：
  - 海岸线附近的高频纹理
  - 大面积中深海的蓝阶过渡
  - 大气层边缘光
  - 云层半透明覆盖
- 这会把“微弱的地表色差”稀释掉。

### 主因 2: 主题 lighting 会压缩贴图差异

当前运行链路里，dayTexture 不是裸贴图直接显示，而是进入 Earth material 后再被主题参数调制：

- `earthMaterial.color`
- `earthMaterial.map`
- `earthMaterial.specularMap`
- `ambientLight.intensity`
- `sunLight.intensity`
- `atmosphereMaterial`
- `cloudMesh`

这意味着 D5b / D5c 的细微 RGB 差异，会被整个渲染管线一起重新加权。

### 主因 3: atmosphere 和 cloud 叠层削弱海洋对比

- atmosphere 不是“只在边缘发光”的极薄层，它本身是一个有颜色和 opacity 的可见球体。
- cloudMesh 也是半透明覆盖层，会把海洋和近岸纹理的局部对比压平。
- 当海区的视觉差异本来就很细时，这种叠层会让 D5c 看起来更像“轻微重新平衡”，而不是“明显不同的贴图版本”。

### 主因 4: sRGB 输出和整体显示链路会继续压缩细节

当前渲染端使用：

- `renderer.outputColorSpace = THREE.SRGBColorSpace`
- 或兼容路径下的 `sRGBEncoding`

这本身不是错误，但会让肉眼对微小色差的感知进一步依赖整体曝光、对比和周围层次。  
如果贴图增量本来就弱，最后呈现出来就更弱。

### 主因 5: UI / 观看条件也会影响判断

- 浏览器窗口大小、设备亮度、屏幕色域、环境光，都会影响 D5b / D5c 的主观分辨率。
- 如果东亚主视角下海面占比高，而 UI overlay 和星空/大气层又在同一屏内参与视觉竞争，贴图差异更容易被“背景化”。

---

## 3. 主要削弱因素排序是什么？

按影响强度从高到低排序：

1. **主题 lighting 与 Earth material 统一调制**
2. **atmosphere opacity / color 的整体压平作用**
3. **cloudMesh 的半透明覆盖**
4. **D5b / D5c 源贴图差异本身偏小，且集中在局部海区**
5. **sRGB 输出与终端显示条件**
6. **UI overlay 和浏览器观看环境**

---

## 4. 下一步应该优先处理 texture fidelity、atmosphere、cloud，还是继续 palette？

### 建议优先级

**优先处理 Texture Fidelity / Atmosphere / Cloud 专项，而不是继续 palette。**

### 原因

- D5b -> D5c 已经证明：继续 palette 调整的边际收益很低。
- 当前问题不是“调色还不够细”，而是“地球上球后的视觉管线把差异吞掉了”。
- 如果不先审计：
  - texture fidelity 是否真的足够在球面上站住
  - atmosphere 是否过厚
  - cloud 是否过雾
  
那么继续做 D5d 只会让更多时间花在被后级管线抹平的差异上。

---

## 5. 是否建议暂停 D5d？

**建议暂停 D5d。**

### 理由

- D5c 已经展示出：palette 继续打磨的收益开始下降。
- 当前瓶颈不是“缺一个更好的 palette”，而是“球面合成后的差异展示不够显著”。
- 继续 D5d 会增加工作量，但不一定能换来肉眼可见的收益。

---

## 6. 是否建议保留 D5c 作为候选但不定版？

**建议保留 D5c 作为候选，但暂不定版。**

### 说明

- D5c 的优势在于：
  - 近岸浅海处理比 D5b 更收敛
  - 一些区域的色相 / 饱和度更稳定
  - 它是一个合理的“高质量候选”
- 但在当前球面渲染链路下，D5c 的视觉收益不足以证明它必须成为最终版。
- 所以更合理的策略是：
  - **保留候选**
  - **暂停定版**
  - **先审 texture fidelity / atmosphere / cloud**

## 7. 逐项审计结论

### 7.1 源贴图 RGB 差异是否足够？

- **足够做候选比较**
- **不足以单独保证上球后明显分化**

### 7.2 上球后是否被 theme lighting 压缩？

- **是**
- 主题 lighting 直接改变贴图可读性，是主要压缩因素之一

### 7.3 atmosphere 是否导致海洋偏灰、偏雾？

- **是，至少在夜间和黄昏段会削弱海洋的纯净对比**
- atmosphere 的颜色与 opacity 会让海洋与天空边界更柔和，但也会让细微地表差异更难读

### 7.4 cloudMesh 是否像半透明雾层？

- **是**
- cloudMesh 本质上就是一层半透明覆盖，当前视觉上会把海洋对比进一步压低

### 7.5 material color / ambientLight / sunLight 是否让贴图差异变弱？

- **是，尤其是 material color 与主题 lighting 的组合**
- 但当前不建议先改灯光；更应该先判断贴图层是否已经足够

### 7.6 texture colorSpace / encoding / tone mapping 是否影响色彩？

- **会影响，但不是本轮主因**
- 它们决定了最终显示的色彩空间与压缩方式，但不是 D5b / D5c 差异变弱的第一责任人

### 7.7 canvas / renderer 的 alpha / opacity / background 混合是否发灰？

- **有贡献，但不是第一主因**
- 透明清屏、叠层和背景合成会让“干净地球边缘”更难获得极高对比

### 7.8 UI overlay 是否影响视觉判断？

- **会**
- 但它更多是“判断条件干扰”，不是贴图差异本身的根因

---

## 8. 最终建议

1. **暂停 D5d**
2. **保留 D5c 作为候选，不定版**
3. **优先进入 Texture Fidelity / Atmosphere / Cloud 专项审计**
4. **不要在当前阶段继续加 palette 复杂度**
5. **如果要验证 D5c 是否值得保留，必须在更干净的球面合成条件下看它**

---

## 9. 结论一句话

**D5b / D5c 的源贴图差异是存在的，但在当前球面渲染链路里被 lighting、atmosphere 和 cloud 叠层显著压缩；因此不建议继续追 D5d，而应先审查 texture fidelity、atmosphere 和 cloud 的展示链路。**
