# Regional Detail Layer v2 — 可行性审计报告

**目的**：评估 RDL MVP 近景清晰度不足的根因，并判断三条增强路径的可行性：
(A) 21.6K satellite source 更充分利用；(B) ETOPO1 地形 / 海底增强；(C) 路网级别矢量层。

**数据来源明确声明**：
- 所有 `source_*` 结论 → 来自 `earth_day_source_21600x10800.jpg`
- 所有 `8k_*` 结论 → 来自 `d5b_design_v3_2_1_8192x4096.jpg`
- 所有 `etopo1_*` 结论 → 来自 `ETOPO1_Ice_g_gdal.grd`
- MVP 阶段 **未使用 ETOPO1**，本报告为首次审计

## 一、数据源基础参数

| 来源 | 原始尺寸 | 分辨率 | 日本区 30°×28° 裁切 | 像素/km（lat 35°） |
|---|---|---|---|---|
| earth_day_source | 21600×10800 | **1.000 arc-min/px** | 1800×1680 px | 1.52 km/px (lon) / 1.85 km/px (lat) |
| d5b_design_v3_2_1 8K | 8192×4096 | 2.637 arc-min/px | 682×546 px | 4.4 km/px |
| ETOPO1 | 21601×10801 | **1.000 arc-min/px** | 1920×1680 px | 1.52 km/px |
| OSM vector roads | vector | 亚米级 | vector | < 0.001 km |

**关键结论**：21.6K source 和 ETOPO1 具有**完全相同的原生分辨率**（均为 1 arc-min）。
两者的 Nyquist 极限：**最小可分辨特征 ~3.0–3.7 km**（采样定理 2× 像素尺寸）。

## 二、21.6K Source 有效精度复核

### 2.1 Laplacian 方差（局部清晰度）对比

| 区域 | 21K native px | 8K native px | 21K 清晰度 | 8K 清晰度（上采样） | 清晰度比值 |
|---|---|---|---|---|---|
| Honshu Alps | 480×420 | 182×160 | 99.4 | 12.7 | **7.80×** |
| Kyushu West | 420×360 | 159×136 | 146.4 | 13.3 | **11.04×** |
| Tokyo / Fuji | 240×240 | 91×91 | 147.7 | 12.0 | **12.35×** |
| Seto Inland Sea | 360×180 | 136×69 | 240.5 | 17.6 | **13.69×** |
| Okinawa Trough | 360×360 | 136×137 | 21.6 | 4.0 | **5.35×** |

### 2.2 结论：21.6K source 有真实细节优势

**结论：是，21.6K source 提供了更高有效细节，但上限受 1 arc-min 分辨率约束。**

- **7–14× 清晰度优势**（Laplacian 方差）验证：像素级纹理细节更丰富
- 特别体现在：濑户内海岛屿岸线、四国山地轮廓、东北海岸锯齿感、九州海峡水道
- **重要限制**：21.6K 的像素尺寸（1.52–1.85 km）意味着以下特征**无法分辨**：
  - 城市街道（~0.01 km）❌
  - 城市街区（~0.1–0.5 km）❌
  - 山峰顶点（富士山顶 ~0.01 km）❌
  - 主要山脊走向（10–50 km）✅
  - 主要海湾开口（>3 km）✅

### 2.3 视觉差异不够明显的真正原因

MVP 中 global_only 与 detail_2048 在 blend=0.75 下视觉差异轻微，原因：

1. **色调来自同一数据系谱**：d5b_v3.2.1 与 21.6K source 均源自 NASA BMNG，陆地纹理色调高度相似
2. **海洋像素贡献小**：深海区域两者均呈深蓝/暗蓝，无法通过卫星影像区分深浅
3. **d5b_v3.2.1 的增强处理反而更美观**：d5b 对海洋色彩做了 H/S 增强，视觉效果优于 21K 原始色调
4. **V 轴 Bug（已修复）掩盖了实际效果**：在 Bug 修复前，blend 完全未生效

## 四、日本山形地势增强判断

### 4.1 ETOPO1 能否增强日本列岛大尺度山地结构？

**结论：是，可以。在 1 arc-min 分辨率下，ETOPO1 能有效展示：**

| 地形特征 | 尺度 | ETOPO1 表现 |
|---|---|---|
| 本州中央山地（Japanese Alps） | ~80km 宽 | ✅ 脊线清晰，海拔梯度可见 |
| 东北山地（奥羽山脉） | ~50km 宽 | ✅ 可见连续山脊 |
| 九州山地 | ~30–50km | ✅ 轮廓可辨 |
| 四国山地 | ~20–30km | ✅ 可辨 |
| 北海道南部山地 | ~40km | ✅ 清晰 |
| 山峰顶点（富士山 3776m）| 0.1km | ⚠️ 仅呈现 3481m（误差 8%） |
| 峡谷 / 河谷（< 5km 宽） | < 5km | ❌ 无法分辨 |

**ETOPO1 分辨率上限的关键说明**：

1 arc-min 在 lat=35°N 约 1.52×1.85 km/格。地形的"平滑化"效果：
- 山脊（线状特征）：宽度 > 3km 的主脊可见，但会被平滑为较低高程
- 富士山例：实测 3481m（ETOPO1）vs 3776m（实际）—— 8% 低估
- 山谷（< 2km）：几乎完全平滑消失
- 海岸线港湾（< 3km 开口）：几何轮廓变形，但大湾可见

**适合做什么**：hillshade 叠加到全局贴图，强化山地立体感，不误导地理精度。

### 5.3 使用 ETOPO1 增强海洋层次的可行性

**可行的增强方案**：

```
海洋区域按深度分层（5级）：
  0 ~ -50m   (浅陆架)     → 淡青色，透明度高
  -50 ~ -200m (陆架边缘)  → 中蓝，轻微渐变
  -200 ~ -1000m (上斜面)  → 蓝色深化
  -1000 ~ -3000m (中深海) → 深蓝
  < -3000m (深盆/海沟)   → 近黑蓝
```

这套方案能显著改善深海区域（现在看起来一片均匀深蓝）的层次感，
同时不违背"非科学地图"的设计约束（颜色处理而非等深线）。

## 六、路网级别可行性判断

### 6.1 当前 raster + ETOPO1 能否达到路网级别？

**结论：不能，且差距是数量级级别的。**

| 层级 | 所需分辨率 | 当前最优（21.6K） | 缺口 |
|---|---|---|---|
| 主干山脉走向 | ~10 km | 1.85 km/px ✅ | — |
| 大型海湾轮廓 | ~5 km | 1.52 km/px ✅ | — |
| 城市区域轮廓 | ~1 km | 1.52 km/px ⚠️ | 仅勉强可见 |
| 主干道路（国道级） | ~0.1 km | 1.52 km/px ❌ | 15× 分辨率缺口 |
| 街道级别 | ~0.01 km | 1.52 km/px ❌ | 150× 缺口 |

### 6.2 路网级别需要的新数据源

如果未来要引入城市/道路细节，需要独立的 **Regional Vector Overlay Layer**：

```
方案草图（仅供参考，不是当前任务）：

  矢量数据源：OpenStreetMap (*.osm.pbf)
  处理方式：
    1. 提取日本 major road (motorway, trunk, primary)
    2. 光栅化为 alpha 叠加纹理（白色微光线条）
    3. 合成在细节贴图之上，仅在极近距离（dist < 1.2）显示

  城市光晕：NASA VIIRS 夜间灯光数据 (~0.25km/px，500m 分辨率）
  港口/机场：OSM 点位 → 图标叠加（Three.js Sprite）
  主干道：OSM 线段 → 极细白色/金色线条纹理
```

**重要设计边界**：
- 矢量层只适合"信号"级别展示（告诉用户"这里有城市"），不是卫星地图
- 不要把 RodiO 做成 Google Earth / Mapbox
- 现阶段不建议实现；需要单独立项讨论

## 七、核心问题回答

### Q1：当前不清晰的根因是什么？

**主因（三层叠加）**：

1. **数据分辨率上限（首要）**：21.6K source 和 ETOPO1 均为 1 arc-min（1.5–1.85 km/px）。在 dist=1.35 时地球覆盖 ~53° 水平角，日本区域约占屏幕 60%。这意味着屏幕上 1 pixel 对应约 4–8 km 真实地面，1 arc-min 级别的细节已接近可视极限。

2. **色调一致性（次因）**：21.6K source 和 d5b_v3.2.1 均来自 NASA BMNG，视觉差异主要体现在纹理噪点而非色调对比，blend 叠加后不够"醒目"。

3. **海洋区域无深度信息（可改进）**：21.6K source 的深海像素是均匀深蓝，无法区分浅陆架、深海盆、海沟 —— 这正是 ETOPO1 能补充的。

### Q2：是否是 shader 问题？

**否**。MVP 验证阶段确认 shader 工作正常（修复 V 轴 Bug 后，97% 可见像素被正确 blend）。Shader 技术路线本身成立。

### Q3：是否是源图有效精度不足？

**是，部分**。21.6K source 比 8K 有 7–14× 清晰度优势（Laplacian），但两者均受 1 arc-min 分辨率上限制约。"更清晰"的上限是更好的纹理细节，而非新的地理信息。

### Q4：ETOPO1 是否能改善山形？

**是，大尺度可行**。日本列岛主要山脉（Alps、奥羽、九州等）在 ETOPO1 1 arc-min 下清晰可见。Hillshade 叠加可有效增强山地立体感。
限制：峰顶精度 ±8%（Fuji 3481m vs 3776m），峡谷/小地形平滑。

### Q5：ETOPO1 是否能改善海湾/海底结构？

**是，有明显增益**。大尺度结构（日本海深盆、东海陆架、冲绳海槽、日本海沟）清晰可见且深度精确。中尺度海湾（东京湾、濑户内海）可辨但有变形。小海湾（< 3km）无法分辨。
**最大价值**：为均匀深蓝的海洋区域添加深度层次，显著提升视觉层次感。

### Q6：路网级别是否需要新数据源？

**是，需要完全不同的数据类**。当前所有 raster 数据均无法达到路网级别。需要 OSM 矢量数据 + 独立渲染层，属于另一个系统范围的工作。

### Q7：RDL v2 应该采用什么资产结构？

**建议的 v2 三层叠加架构**：

```
Layer 0（全局基础）: d5b_design_v3_2_1_8192x4096.jpg
  ├── 覆盖全球
  └── 保持 ocean 色彩增强处理

Layer 1（陆地细节）: 21.6K source → 色调匹配后的区域 detail tile
  ├── 仅覆盖陆地 / 海岸带
  ├── 从 21.6K source 裁切（已验证有效，10× 清晰度）
  ├── 需要色调匹配（与 d5b_v3.2.1 ocean 色调对齐）
  └── Blend ≤ 0.5 以避免 ocean 色差

Layer 2（海洋深度）: ETOPO1 → 按深度分层的 ocean tint 贴图
  ├── 仅覆盖海洋区域（elevation < 0 mask）
  ├── 5 深度级别颜色映射（见第五节）
  ├── 与 Layer 0 ocean 做 25–40% blend
  └── 无需距离自适应（全局可见）

Layer 3（未来可选）: 矢量道路/灯光叠加
  └── 单独立项，超出当前范围
```

### Q8：是否建议继续做日本区域 v2 视觉增强样板？

**是，建议分两步**：

**Step 1（可立即执行）**: 生成 ETOPO1 海洋深度贴图
- 从 ETOPO1 为日本区域生成 ocean depth color tile（5 深度级）
- 在 demo 中叠加到海洋区域，验证视觉层次效果
- 此步不需要新数据，成本低，预期效果最明显

**Step 2（需色调匹配工作）**: 21.6K 陆地 detail 色调对齐
- 对 21.6K 裁切贴图做 color grading，使 ocean 区域与 d5b_v3.2.1 对齐
- 将 blend 范围拆分：陆地 blend=0.6–0.8，海洋 blend=0.0（或仅 ETOPO1）
- 预期：陆地细节清晰 + 海洋维持 d5b 美观色调
