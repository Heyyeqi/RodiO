# 关键验证:菱形/紫色纹路到底是贴在地球网格上,还是跟屏幕位置绑定的独立图层

本轮阶段:决定性验证，请严格按步骤做，这次要直接看"纹路会不会跟着转"，不是"关掉某层纹路还在不在"
允许操作:控制台命令 + 截图/录屏

---

## 背景(重要纠正)

之前的诊断报告里有一条线索："用户最早发现纹路不随地球旋转"，但报告后续认为这是"误导信号"，理由是"纹路其实贴在地球表面，只是恰好出现在南美洲/南非这些固定地理区域，看起来像不动"。

**用户明确表示：持续观察确认这个纹路确实不随地球转动。** 这个解释站不住——如果纹路真的贴在地球mesh表面（跟着UV走），地球一转动/相机一移动，这个纹路必然会跟着移动到屏幕的不同位置，不可能长期"恰好"停在原地。

**之前的排查方法("关掉某一层，纹路还在不在")只能证明"这个纹路的内容不是那一层产生的"，不能证明"这个纹路是不是贴在地球网格上"——这次需要专门测后者。**

## 请按这个方式验证(这是本轮最关键的测试)

### 1. 让地球明显转动/相机明显移动，连续观察纹路的屏幕位置

```js
window.earth3d.setGramPrimitive('longitudeDrift')  // 让地球经度持续旋转
```
（如果这个方法不适用于当前候选，改用 `window.earth3d.transitionToComposition('farOrbit', {duration:5})` 之类的方式让镜头/地球产生明显的相对运动）

**连续观察至少10秒**，期间每隔2-3秒截一张图（至少4-5张连续截图）。**重点看：那个菱形/紫色纹路，在这几张截图里，是跟着地球表面的地理特征（比如某个岛屿、海岸线）一起移动，还是始终停留在屏幕的同一个位置（不管地球转到哪里，纹路都在画面同一处）？**

### 2. 如果确认纹路是"屏幕锁定"（不跟着地球转），请检查这几个屏幕空间图层

- `earlyMorningSkyScene`/`earlyMorningSkyCamera`（背景天空渐变平面，正交相机渲染，`earth3d.js:2260`附近）
- `earlyMorningRimOverlayScene`/`earlyMorningRimOverlayCamera`（rimGlow的Rim Overlay + Inner Horizon Veil，同样是正交相机全屏渲染，`earth3d.js`里`renderer.render(earlyMorningRimOverlayScene, earlyMorningRimOverlayCamera)`那几处）
- 检查这几个屏幕空间shader（`_emSkyPlaneMat`/`_emRimOverlayMat`/`_emInnerVeilMat`）有没有用到某个会产生菱形重复图案的纹理采样，或者shader数学本身（比如某个基于`gl_FragCoord`或者固定UV重复的pattern生成逻辑）产生了这个重复图案

**这次请先做第1步，把连续截图/录屏发过来，明确回答"纹路到底跟不跟着地球转"，这个结论决定了后续往哪个方向查，不要跳过直接下结论。**
