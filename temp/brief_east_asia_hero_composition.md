# Brief:新建候选镜头预设 eastAsiaHeroV1——修正构图重心偏左问题

## 背景

当前默认视角(`globe`预设)存在构图问题:中国/日本/东南亚内容挤在画面左侧,右侧西太平洋大片空白,右下角澳大利亚被生硬截断,画面整体感觉重心偏左、有轻微歪斜下坠感,地球顶部弧线离歌曲标题太近。

**这份brief参考了外部协作者(Evan)提出的诊断和方案,已经用代码核实过根本原因,对Evan原方案做了一处关键修正——不是简单调经纬度去"迁就"现有问题,而是直接修正问题的源头。**

## 根因(已核实,不是猜测)

`pwa/earth3d.js:2742`:
```js
const VISUAL_TARGET_NDC = new THREE.Vector2(0.25, -0.24)
```
这个写死的常量决定了"目标经纬度对应的那个点,永远被钉在屏幕NDC坐标(0.25, -0.24)这个固定位置"——NDC的0是屏幕中心,0.25就是明显偏左、-0.24是明显偏下。这是`updateVisualTargetDir()`函数(2748-2776行附近)用来算地球朝向的锚点,`getTargetOrientation()`(5152-5184行附近)再拿这个方向去算地球该转到什么朝向。

**这才是"重心偏左"的真正原因,不是经纬度选得不对**——不管`CAMERA_PRESETS`里的`lat`/`lon`怎么调,最终结果都会是"某块内容被钉在这个偏左偏下的位置",整体构图偏左这件事本身不会因为调经纬度而改变。所以这次的核心修复是**把这个NDC锚点常量往画面中心挪**,而不是主要靠调经纬度去补偿。

另外,现有`CAMERA_PRESETS`结构(`pwa/earth3d.js:6176`附近)完全没有"Roll(相机滚转)"这个字段,`quaternionFromBasis()`(396-429行附近)构建朝向时也没有额外的滚转控制。用户反馈的"歪斜下坠感"大概率就是这个偏左偏下锚点造成的副作用,不是一个独立的滚转问题——**这次先不新增滚转控制机制,等锚点修正之后再看这个"歪斜感"是否已经解决**,避免不必要地去碰四元数计算这块更复杂、风险更高的代码。

## 要做的事

### 1. 新建独立候选预设 `eastAsiaHeroV1`,不覆盖现有`globe`预设

在`CAMERA_PRESETS`(`pwa/earth3d.js:6176`附近)里新增一项,不删除、不修改`globe`及其他现有7个预设的任何数值。

### 2. 核心修复:调整`VISUAL_TARGET_NDC`(这是这次改动的重点)

**注意`VISUAL_TARGET_NDC`目前是模块级共享常量,不是per-preset的**——如果直接改这一个全局常量,会影响所有使用`centerMode:false`的预设(`globe`/`heroClose`/`oceanView`等),不只是新预设。请先判断:
- 如果`VISUAL_TARGET_NDC`改成更居中的值(比如`(0.05, -0.05)`附近,具体数值你可以视觉调试确定)对`globe`等其他现有预设也是改善而不是破坏,那就直接调整这个全局常量,这是最直接、最推荐的做法;
- 如果调整这个全局常量会让其他预设的构图变差,那就需要把这个常量改造成per-preset可配置的(比如给`CAMERA_PRESETS`每一项加一个可选的`targetNdc`字段,没有指定时用现有的`(0.25,-0.24)`做默认值兜底,`eastAsiaHeroV1`专门指定一个更居中的值),这样改动范围更大一些,但不影响其他预设。

**请先在浏览器里视觉测试一下把这个常量改成居中值之后,`globe`预设的构图效果如何,再决定用上面哪种方式**,把你的判断和理由写进最终报告里。

### 3. 配合性微调(在锚点修正的基础上做,不是主要修复手段)

- 经纬度:可以在锚点调整之后,再视觉微调`eastAsiaHeroV1`的`lat`/`lon`,让中国东部、日朝、东南亚整体呈现更好,不用严格照搬"经度西移12-18°/纬度北移4-8°"这两个具体数字,那是针对"没修锚点"这个前提算出来的补偿值,锚点修正之后这两个数字大概率不再适用,以实际视觉效果为准。
- FOV:可以收窄15-20%左右,同时增加`cameraOffsetZ`(相机距离)做补偿,维持地球在画面里的大小基本不变,减少广角导致的边缘大陆拉伸感。已经确认过屏幕空间rim辉光投影(`updateEarlyMorningRimProjection()`)是每帧根据真实相机FOV/距离重新计算的,不会因为FOV变化而出问题,不用额外处理。
- 地球整体视觉占比可以缩小5-8%左右(通过增加相机距离,不是缩小FOV来实现)。

### 4. 画面整体下移12-20px(需要新增机制,现有代码里没有)

现有代码没有任何"整体挪动地球在屏幕上位置"的机制(没有`camera.setViewOffset()`调用,没有canvas的CSS transform)。**推荐用最简单的CSS transform方式实现**,不要用`camera.setViewOffset()`(那个会改变实际投影矩阵,可能影响rim辉光那套逐帧重算投影的逻辑,增加不必要的复杂度和风险)。

具体做法:给`renderer.domElement`(承载地球画面的canvas)加一个可控的CSS `transform: translateY(...)`,只在`eastAsiaHeroV1`这个预设生效时应用这个偏移(不要影响其他预设或默认状态)。

## 严格的修改边界(照抄Evan原brief的范围限定,这部分定得很好,原样保留)

**只允许修改**:camera preset、camera position/target、FOV、camera distance、earth orientation、经纬度朝向、`VISUAL_TARGET_NDC`(或者改造后的per-preset版本)、canvas的screen transform偏移、与这个候选预设直接相关的调试配置。

**禁止修改**:`THEME_VISUAL_CONFIG`、任何时段主题的颜色参数、shader、shader uniform、mapColor、emissiveColor、emissiveIntensity、atmosphere、ambient lighting、nightGrade、城市灯光、海洋颜色、云层、星空、rimGlow的颜色/强度参数(投影计算逻辑本身不用动,那是自动适配的)、bloom、CSS整体布局(除了这次新增的canvas偏移)、播放器控件、歌曲标题位置、手机端交互逻辑、地球旋转速度和音乐响应逻辑(`_precomputeMotion`那一整套不要碰)。

不要通过提高灯光、辉光、城市亮度或改变海洋颜色来平衡构图。
